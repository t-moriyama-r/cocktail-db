# 楽天ウェブサービス(楽天市場の商品検索 API)

楽天市場の商品の情報(商品名・画像・価格)を取るための API。この資料は、収集(#72)・情報をいつまで出してよいかの決まり(#247)を作るときに見る。Amazon の分は `docs/amazon-creators-api.md`。

- 書いてあるのは、公式の資料で確かめたことだけ。確かめた日は **2026-10-26**。使う前に出典を開いて変わっていないかを確かめる
- 公式の資料は 4 種類ある。どれも楽天グループが出しているもの
  - 規約: 楽天ウェブサービス規約(`webservice.rakuten.co.jp/guide/rule`)。ページの末尾に「2006年12月14日 制定」「2012年6月28日 改定」とある(最後の改定)
  - API のリファレンス: `webservice.rakuten.co.jp/documentation/…`。更新日は書かれていない
  - ヘルプ(よくある質問): `webservice.faq.rakuten.net`。記事ごとに更新日がある(下に書いた日付は、ヘルプの記事の一覧の API が返す本文の最終編集日)
  - お知らせ: 公式のブログ(`rakuten-webservice.tumblr.com`)
- 規約・ヘルプの文言は、出典の日本語をそのまま引いている
- 公式の資料に書いていないことは「公式に記載なし」と書いた。確かめていないことは、最後の「確かめていないこと」にまとめた
- アプリ ID・アクセスキー・アフィリエイト ID の値は、このリポジトリに書かない(GitHub の Secret かサーバーの `.env` に置く)

## 2. アプリの登録と、呼ぶときに要るもの

- API を呼ぶには、アプリを登録して **アプリ ID(`applicationId`)** と **アクセスキー(`accessKey`)** を発行する。アプリの登録の必須の項目は「アプリケーション名、アプリケーションURL、アプリケーションタイプ、許可されたWebサイト、データ利用目的、予想QPS」
- アプリは 1 人 5 つまで。「アクセス制限については基本的にアプリごとに制御いたします。」
- アフィリエイト ID(`affiliateId`)は 1 人 1 つで、アプリに共通
- 商品検索 API(`20260701`)では、`applicationId` と `accessKey` の **両方が必須**。`accessKey` はヘッダーか入力パラメーターのどちらかで渡せる(ヘッダーの名前もパラメーターの名前も `accessKey`)
- 呼び出し先:

  ```
  https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701?applicationId=<アプリID>&accessKey=<アクセスキー>&affiliateId=<アフィリエイトID>&keyword=<URL エンコードした語>&formatVersion=2
  ```

- `keyword` と `sort` の値は、値の部分だけを UTF-8 で URL エンコードする(URL 全体をエンコードしない)
- 規約 第5条: アプリ ID は「他人に知られることがないよう責任をもって管理するもの」とする
- API は無料(ヘルプ「楽天ウェブサービスは無料で利用できますか？」)
- 規約 第3条: アフィリエイトの報酬を得る目的で使うときは「楽天アフィリエイト」でリンクを作り、楽天アフィリエイトパートナー規約に従う。規約 第10条(5): 楽天アフィリエイトの対象の商品に、ほかのアフィリエイトを使わない
- 「許可されたWebサイト」の登録が、呼び出しのときに何で確かめられるか(Referer のヘッダが要るか、など)は **公式に記載なし**(読んだ範囲のリファレンスとご利用ガイドには書かれていない)

## 3. 取った商品の情報を保存してよいか・保存してよい期間

### 3.1 キャッシュしてよい期間

ヘルプ「各APIから取得したデータを表示する場合、どのくらいの頻度で更新する必要がありますか？」(最終編集 2024-04-01)の (1) の原文:

> (1)データのキャッシュに関して
> デベロッパーは、一般的に以下の期間であれば、データをキャッシュする目的で楽天グループ（以下、「当社」とする。）の知的財産を格納することができます。
> ・商品の価格情報、および販売可能情報：24時間
> ・その他の情報：3か月間
> ※下記(3)の当社の権利に限定されることなく、当社はいつでも上記の当社の知的財産を削除するようデベロッパーに指示することができ、デベロッパーは、かかる指示をただちに遵守することに了承し、合意します。

- 価格・販売可能かどうか: **24 時間**
- ほかの情報(商品名・商品の URL・画像の URL など): **3 か月**
- 楽天から消すよう言われたら、すぐに消す
- この期間は規約の本文には無く、ヘルプにだけある。規約 第1条は、ルール・ガイドライン・ヘルプも「本規約等」として守るものとしている

出典: https://webservice.faq.rakuten.net/hc/ja/articles/900001974343

### 3.2 規約の決まり

規約 第10条(禁止行為)の原文(関係する号だけ):

> (7) ウェブサービスおよびアプリケーションを通じて得た情報（商品情報、ユーザの情報を含むがこれに限られない）に関し、当社が別途定める目的以外に使用し、または当社が別途定める以外の複製または改変をすること
>
> (9) 不特定または多数人と情報を共有することを可能にする場所にウェブサービスを通じて得た情報またはアプリケーションを保管すること

- (7) の「当社が別途定める目的」は、ヘルプ「各APIで取得した情報はどのような目的で利用できますか？」(最終編集 2020-07-30)に「利用者ソフトウェア上で当社の商品を紹介し、かつ当社内の当該商品のページにリンクを設ける目的でご利用いただけます。また、APIから取得した情報をこの目的以外で複製または改変することは禁止します。」とある
- (9) のとおり、取った情報(API の応答)を、誰でも見られるところ(このリポジトリなど)に置かない
- 規約 第1条: 「商品情報」は「商品名、店舗名、ＵＲＬ、画像、商品説明、価格に関する情報を含むがこれに限られません」
- 規約 第10条 2: 楽天は、禁止行為にあたるときコンテンツの削除を求めることができ、デベロッパーは直ちに従う

出典:
- 楽天ウェブサービス規約(第1条・第10条): https://webservice.rakuten.co.jp/guide/rule
- ヘルプ「各APIで取得した情報はどのような目的で利用できますか？」: https://webservice.faq.rakuten.net/hc/ja/articles/900001974363

### 3.3 公式に記載なし

- **画像そのもの(画像のファイル)を自分のサーバーに保存してよいか**: 公式に記載なし。3.1 の「その他の情報：3か月間」に画像のファイルが入るのか、画像の URL だけなのかは書かれていない(Amazon は画像の保存を禁じている。`docs/amazon-creators-api.md` の 9.1)
- **商品のコード(`itemCode`)を、いつまで持ってよいか**: 公式に記載なし。3.1 の「その他の情報」として 3 か月と読むのか、識別子として別に扱うのかは書かれていない(Amazon は ASIN を期限なく持ってよいと書いている)
- 画像の URL の後ろのパラメーター(`?_ex=` など)を外して使うことが、第10条(7) の「改変」にあたるか: 公式に記載なし

## 4. 価格を出すときの決まり

### 4.1 取り直す頻度と、取得時刻・決まった文言

3.1 と同じヘルプの (2)・(3) の原文:

> (2)表示されるデータの更新頻度に関して
> デベロッパーは、アプリケーション上またはアプリケーション内に価格情報または販売可能情報を表示する場合、情報を少なくとも1週間に1回、各APIから新たに取得した情報に刷新し、再表示しなければなりません。
>
> (3) データ取得日時の表示に関して
> デベロッパーは、１時間に１回以上データを更新しない場合は、価格情報または在庫情報等の情報に隣接した位置に更新時刻・日時を記載しなければなりません。その際、下記の免責事項を、価格情報または販売可能情報等の情報に隣接して掲載するか、ハイパーリンク等の方法で掲載しなければなりません。
> 「このサイトで掲載されている情報は、●●（サイト名）の作成者により運営されています。価格、販売可能情報は、変更される場合があります。購入時に楽天市場店舗（www.rakuten.co.jp）に表示されている価格が、その商品の販売に適用されます。」

- 価格・販売可能かどうかを出すなら、**少なくとも 1 週間に 1 回** 取り直して出し直す
- **1 時間に 1 回以上取り直さないなら**、価格(在庫など)の **すぐ横に、更新した時刻・日時** を出す
- そのとき、上の **免責の文言**(`●●` はサイト名)を、価格のすぐ横に出すか、リンクなどで見られるようにする
- 3.1 の (1)(価格は 24 時間までキャッシュしてよい)と (2)(1 週間に 1 回は取り直す)は、同じヘルプの中で期間が違う。どちらに合わせるかは #247 で決める。ヘルプの文面からは、どちらが優先かは読み取れない
- Amazon と違い、日付を省いてよい場合(同じ日のうちは時刻だけでよい、など)は **公式に記載なし**

出典: https://webservice.faq.rakuten.net/hc/ja/articles/900001974343

### 4.2 クレジットの表示

- 「楽天ウェブサービスによって提供されたAPIを利用するすべてのサイトやアプリには、クレジットを表示する必要があります。」
- 形式は画像(221×21・311×30)かテキスト(「Supported by Rakuten Developers」)。公式の HTML のソースをそのまま使い、ソースも画像も変えない
- 表示する位置は自由。ただし、楽天ウェブサービスを使って作ったことが分からなくなる出し方はしない。楽天が提供しているサイトだと誤解させる表示はしない
- 守らないと、API の利用を止められることがある
- 規約 第13条: 楽天が求めるときは、アプリに出す商品の情報が楽天グループの提供したものであることを、楽天が別に決める方法で出す

## 6. 商品のコード(`itemCode`)を指定して 1 件を取り直す

- 専用の「1 件を取る」API は無い。**商品検索 API(`IchibaItem/Search`)の入力パラメーター `itemCode`** で指定する
- `itemCode` は、商品検索 API などの出力に入っている「`shop:1234`」の形の値(例は公式のもの)。`keyword`・`genreId`・`itemCode`・`shopCode` のどれか 1 つが必須で、`itemCode` だけでもよい
- `availability`(販売可能)は既定が `1`(販売可能な商品のみ)。`0` にするとすべての商品。売り切れた商品を取り直したときにどう返るかを見るなら `0` を付ける(どう返るかは確かめていない)
- `elements` で、返してほしい出力パラメーターだけにしぼれる(例: `elements=itemName,itemPrice,itemUrl,affiliateUrl,mediumImageUrls,availability`)

  ```
  https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701?applicationId=<アプリID>&accessKey=<アクセスキー>&affiliateId=<アフィリエイトID>&itemCode=<URL エンコードした shop:1234 の形の値>&formatVersion=2
  ```

- 公式に記載なし:
  - `itemCode` を指定したとき、必ず 1 件だけ返るか
  - 1 回に複数の `itemCode` を指定できるか(書かれていないので、1 回に 1 件として扱う。1 秒に 1 回なので、N 件の取り直しには N 秒以上かかる)
  - 商品が消えた・売り切れたときに、`404`(`not_found`。リファレンスのエラーの表には「対象のデータが存在しなかった場合」とある)が返るのか、`count` が 0 の `200` が返るのか
- 商品価格ナビ製品検索API(`Product/Search`)の一覧の説明にも「商品コードから商品情報を取得」とあるが、これは別の API(価格比較の製品)。この取り直しには使わない

出典:
- 楽天商品検索API(入力パラメーター `itemCode`・`availability`・`elements`、エラー): https://webservice.rakuten.co.jp/documentation/ichiba-item-search
- API一覧: https://webservice.rakuten.co.jp/documentation

旧システム(本番の BE。`App\Classes\Rakuten`・`App\Classes\Factory\RakutenFactory`・`App\Classes\Factory\AffiliateFactory`・`AffiliateController`)のしていたこと。秘密の値と設定の名前は書かない。

- 呼び先: `app.rakuten.co.jp/services/api/IchibaItem/Search/20170706`(1 のとおり、もう使えない)。`applicationId`・`affiliateId`・`keyword`・`formatVersion=2` を付けていた。`accessKey` は無い(当時は要らなかった)
- `genreId=510915`(楽天市場のジャンル「ビール・洋酒」)をいつも付けていた。呼ぶ側は「洋酒でない(カテゴリの種類が 4 以上)」ときはジャンルを付けない引数を渡しているが、受け取る側の関数がその引数を受け取っておらず、効いていない
- 検索語は、そのカテゴリ・中カテゴリ・銘柄の名前。結果の **先頭の 1 件だけ** を使う。0 件なら楽天の分は空のまま
- 呼び出しが失敗したら(検索語に空白があるとき、と旧のコメントにある)、空白を取り除いた語で 1 回だけやり直す
- 保存していた項目: 商品名(`itemName`)・価格(`itemPrice`)・商品のリンク(`affiliateUrl`)・画像の URL(`smallImageUrls` の先頭から `?_ex=` 以降を取り除いた URL。旧のコメントは「画像URLはオリジナルサイズを保持」)・検索結果のページへのリンク(下)
- 検索結果のページへのリンクは、API の値ではなく自分で組み立てていた: `https://hb.afl.rakuten.co.jp/hgc/<アフィリエイトID>/?pc=` に、楽天市場の検索結果のページ(`search.rakuten.co.jp/search/mall/<語>/510915/`)を URL エンコードして付けた形。リファレンスの「アフィリエイトに関して」にある、商品 URL からアフィリエイト URL を作る形(`http://hb.afl.rakuten.co.jp/hgc/[アフィリエイトID]/?pc=[商品URL（PC）]&m=[商品URL（モバイル）]`)を、検索結果のページに当てはめたもの。検索結果のページに使ってよいかは公式に記載なし
- 商品のコード(`itemCode`)は持っていなかった。取り直すときは、名前でもう一度検索していた
- 取り直し: 収集を呼ぶたびに、最後に取ってから **7 日より古い** 行を **5 件まで** 取り直す(人が価格を手で入れた行は除く)。1 件ごとに 1 秒待つ(旧のコメントは「API制限を回避したいので1秒待つ」)。Amazon と楽天をまとめて取り直すので、楽天の分の日付だけを別に持ってはいない
- 画面へは、取った日を `Y/m/d`(日付だけ。時刻は無い)で返していた。免責の文言とクレジットを出していたかは、画面の側で確かめていない
