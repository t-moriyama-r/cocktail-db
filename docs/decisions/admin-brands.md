# 管理画面の銘柄の一覧・新規・編集

#64 で決めたこと。決めたのは #64 の本文の「追記: 旧の画面で確かめた仕様」(オーナーが書いた)で、ここはそれを、テストの表から指せる「旧との差分」の節にまとめ、画面を作るときに決めた細かいところを足したもの。API(検証・所属を変えたときの材料の追随)は #314 で、その差分は #314 の本文の「旧との差分」にある。

## 決まったこと

1. メニューの項目は「銘柄」1 つにし、一覧(`/admin/brands`)を開く。新規は一覧の上の「新規」のリンク(`/admin/brands/new`)から、編集は一覧の 1 行(`/admin/brands/<ID>`)から開く
2. 一覧の 1 行は「名前(英名)」の編集画面へのリンクと、その後ろに括弧で所属を出す。所属は、根を除いたパンくずのうち、いちばん上の段と所属のノード(末尾)だけを「/」でつなぐ(`docs/decisions/public-detail.md` の決まったこと 3 と同じ選び方。間の段は省く)。その段の有名な銘柄がこの銘柄なら、段の名前の前に ★ を付ける
3. フォームの並びは、旧と同じく、所属 / 名前・英名・度数 / メジャー・お気に入り / 説明 / YouTube と開始位置 / 画像 / リンクテキスト・リンクURL / 送信。#64 の追記は「メジャー・お気に入り」を「リンクテキスト・リンクURL」の後に書いていたが、追記の意図は「旧と同じ」で、旧の画面(`NamesAndDescription.vue` と本番の画面のビルド `production-public/3.js`)ではメジャー・お気に入りは度数の後・説明の前にあるので、旧に合わせた
   - 欄の名前は、旧の「Name」「%」「Youtube」を「英名」「度数(%)」「YouTube」にする(何の欄か分かるように)。画像の欄は旧の「画像ファイルをアップロードしてください」を「画像」にする
4. 所属は木の部品(#297)の単一選択で、根の下のどの深さのノードでも選べる。根は見出しにして選べなくする。選んでいる所属を、根を除いたパンくずで木の上に出す。木は検索フォームの API(`GET /api/search-form`)の木を使う
5. 度数の欄は数字と `.` だけを 4 文字まで受け付ける(全角の数字は半角にする)。開始位置は数字だけを、時は 1 桁、分・秒は 2 桁まで受け付け、旧と同じく数にして出す(数字の無い文字は 0、`05` は `5`)。英名は欄を離れたときに全角の英数字を半角にする
   - メジャー・お気に入りは、押すたびに入れ・外しができる普通のチェックボックスにする
6. 検証は API に任せ、送る前に画面では確かめない。保存の 422(有名な銘柄の所属を部分木の外へ移すときの理由を含む)は項目ごとに欄の下に出し、画面を移らない(`docs/decisions/admin-screens.md` の既定)
7. 保存できたら一覧へ戻る

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-brands.md)` としてここを指す。旧の画面のソース(cocktail-legacy の `laravel6/resources/js/Admin/Super/BrandList.vue`・`ListComponent.vue`・`Detail/BrandEdit.vue`・`Detail/component/NamesAndDescription.vue`)を読んで書いた。旧システムを動かして確かめてはいない。

- メニュー: 旧は「銘柄新規」「銘柄編集」の 2 つの項目だった → 新は「銘柄」1 つにし、新規は一覧の上のリンクから開く(決まったこと 1。カクテルの一覧(#126)と同じ形)
- 一覧の所属: 旧は「(★カテゴリ/★ミドル)」の 2 段 → 新は根を除いたパンくずのいちばん上の段と所属のノードの 2 段で、間の段は省く(決まったこと 2。2 段までの木では旧と同じに見える)
- 度数の欄の長さ: 旧は 4 文字の目安(`counter`)を出すだけで、5 文字目からも入った → 新は 4 文字で止める(決まったこと 5。#64 の追記)
- 欄の名前: 旧は「Name」「%」「Youtube」「画像ファイルをアップロードしてください」 → 新は「英名」「度数(%)」「YouTube」「画像」(決まったこと 3)
- メジャー・お気に入り: 旧は押したときに `$emit('update:is_major', !!$event)` で、イベントを真偽値にしていたため、押すと必ず「入れる」になり、外せなかった(旧の不具合) → 新は押すたびに入れ・外しができる(決まったこと 5。外せない欄を残す理由が無いので直した)
- 送る前の確かめ: 旧は送る前に、画面で必須(所属・名前・英名・度数・説明)と度数が数かを確かめ、足りなければ送らなかった → 新は画面では確かめずに送り、API の 422 を項目ごとに出す(決まったこと 6)
- 保存できたとき: 旧はメニュー(`/admin`)へ戻った → 新は一覧へ戻る(決まったこと 7。#64 の追記)
- 名前・英名の重なり: 旧は名前・英名を変えると問い合わせて、欄の下に「[Warn]同じ名前が存在しています」を出した → 新は、問い合わせる API(#632)が無いので、この画面ではまだ出さない(#633 で旧と同じく出すようにする)

所属を任意の深さのノード 1 つで選ぶこと(旧はカテゴリとミドルの 2 つ)は #314 の「旧との差分」、一覧の絞り込みとページング・保存に失敗したときの出し方は `docs/decisions/admin-screens.md` の「旧との差分」にある。
