# 言い換え辞書の読み替え先の解決

#316 で決めたこと。言い換え辞書(`paraphrases`)は読み替え先を名前(`converted`・`middle`)で持つ(`docs/schema.md` の「paraphrases」)。管理 API(`/api/admin/paraphrases`)は、保存のときにその名前が木のノードか銘柄に解決できるかを確かめ、一覧と取得では解決した先を返す。解決は `ParaphraseTargets` が行う。

## 決まったこと

1. **名前の比べ方**: 旧の `DictionaryController@serachFromWords` と同じく、`name_search` の形(`NameNormalizer`。#171)にそろえて比べる。根(旧の種別)は読み替え先にしない(旧は種別を探していなかった)
2. **`middle` が無いとき**: `converted` を、根のすぐ下のノード(旧のカテゴリ)→ 銘柄 → それより深いノード(旧のミドル)の順に探す(旧と同じ順)。同じ名前のノードが複数あれば、浅いもの、同じ深さなら ID の小さいもの(`CategoryTree::findByName`)。銘柄は ID の小さいもの
3. **`middle` があるとき**: `converted` のノード(根を除き、上と同じ選び方)の配下(子孫すべて)から、`middle` の名前のノードを探す。`converted` は銘柄にできない
4. **解決できないとき**: 保存(追加・更新)は 422(`converted` が見つからない・銘柄なのに `middle` がある → `converted`、配下に `middle` が無い → `middle`)。一覧と取得は、その語の `resolved` を null にして返す(ノードの名前が後から変わると、保存してあった語が解決できなくなるため)
5. **返す形**: `resolved` は、ノードなら根からのパンくず(末尾がそのノード)と `brand: null`、銘柄なら所属するノードまでのパンくずと銘柄(カクテルの詳細の材料と同じ形)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/paraphrase-target.md)` としてここを指す。旧には言い換え辞書を保存する画面が無い(一覧を出してフォームに読み込むだけ)ので、保存の検証(422)は旧に無い。旧の挙動は本番の旧ソース(`laravel13/`)から読み取ったもので、旧を動かして確かめてはいない。

- 解決できない名前: 旧は `serachFromWords` が null のプロパティを読んで 500 → 新は保存では 422、一覧・取得では `resolved: null`
- `middle` を探す範囲: 旧は `converted` のカテゴリの直下の子(ミドル)だけ → 新は `converted` のノードの配下すべて(木の深さが決まっていないため)
- `middle` があるときの `converted`: 旧は根のすぐ下のノード(カテゴリ)だけを探し、無ければ 500 → 新はそれより深いノードも探す(無ければ 422)
