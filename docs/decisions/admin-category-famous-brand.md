# 管理画面のノードの編集フォーム(有名な銘柄の選択と、その場での作成)

#309 で作った、ノードの新規・編集フォーム(`docs/decisions/admin-category-form.md`)の有名な銘柄の欄の決まり。項目は #309 の本文(オーナーが書いた)のとおり。必須かどうか・候補の範囲は #155・#158(`docs/decisions/strength.md`)、保存の API(`famous_brand_id`・`brand_*`)は #121 で決まっていて、その差分は #121 の本文と `docs/decisions/strength.md` の「旧との差分」にある。ここは、画面を作るときに決めた細かいところと、テストの表から指せる「旧との差分」の節。

## 決まったこと

1. 有名な銘柄の欄は、フォームのリンクテキスト・リンクURL の後、送信の前に出す(旧の `CategoryEdit.vue`・`MiddleEdit.vue` と同じ並び)。根(API の `famous_brand_requirement` が `none`)では出さない(根には有名な銘柄を入れられない。`docs/decisions/strength.md` の「根のノード」)
2. 選択の欄の候補は、そのノードの部分木の銘柄(API の `famous_brand_candidates`。#158)。先頭に「(新しく作成する)」を置き、続けて「名前(英名)」を名前の順に並べる(旧の `Helper.aiu` と同じく、カタカナをひらがなに、全角の英数字を半角に、英字を小文字にそろえて、文字コードの大小で比べる)
   - 開いたときは今の有名な銘柄を選んでおき、無ければ「(新しく作成する)」にする(旧と同じ)
   - 候補が 0 件(新規のノードと、部分木に銘柄が無いノード)なら、選択の欄を出さず「-有名な銘柄を入力して下さい-」と出す(#309 のやること 1)
3. 「(新しく作成する)」のときは、その場で作る銘柄の欄を、銘柄のフォーム(`docs/decisions/admin-brands.md` の決まったこと 3・5)と同じ並び・同じ受け付け方で出す。名前・英名・度数(%) / メジャー・お気に入り / 説明 / YouTube と開始位置 / 画像 / リンクテキスト・リンクURL
   - 欄の見えるラベルはノードの欄と同じ短い名前にし、読み上げる名前は「有名な銘柄の名前」のように「有名な銘柄の」を付けて、ノードの欄と見分けられるようにする(API の検証のメッセージの欄の名前と同じ)
   - 既存の銘柄を選び直しても、文字の欄の入力は残す(「(新しく作成する)」に戻すとそのまま出る)。選んでいた画像は外す(ファイルの欄は隠すと選択が消えるので、見えない画像を送らない)
   - 名前・英名は、値を変えて欄を離れたら(旧の `@change`)重なりを問い合わせ(`GET /api/admin/brands/duplicates`。#632)、重なれば欄の下に「同じ名前が存在しています」を出す(#723)。銘柄のフォーム(`docs/decisions/admin-brands.md` の決まったこと 8)と同じく、所属によらず銘柄全体で比べ、英名は半角にした値で問い合わせ、空にしたら問い合わせずに知らせを消し、欄は誤りの印にしない。作るのは新しい銘柄なので、どの銘柄も除かずに比べる(旧も同じ。旧は問い合わせに親を送っていたが、銘柄のときは使わずに表の全体で比べていた)。知らせるだけで、送信は止めない(旧と同じ)
   - 知らせが出たまま既存の銘柄を選び直し、「(新しく作成する)」に戻したときは、残っている名前・英名とともに知らせも残して出す(入れた値はそのまま重なっているので)
4. 送るのは、既存の銘柄を選んだら `famous_brand_id` だけ、「(新しく作成する)」なら `brand_*` の欄すべて(空の欄も空のまま)。YouTube とリンクテキスト・リンクURL は銘柄の欄の値を送る(#309 のやること 4)
5. 必須かどうかは API が根の役割で決め(根の役割が無い部分木では必須、ソフトドリンク・その他では銘柄の名前・英名・度数・説明のどれかを書き始めたら残りも必須。#155・#158)、画面では確かめない(`docs/decisions/admin-category-form.md` の決まったこと 7)。422 のメッセージは、`famous_brand_id` は選択の欄の下に、`brand_*` はその場で作る銘柄の欄の下に出す(欄を出していない項目は、送信の下にまとめて出す)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-category-famous-brand.md)` としてここを指す。旧の画面のソース(cocktail-legacy の `laravel6/resources/js/Admin/Super/Detail/component/FamousBrandSelect.vue`・`NamesAndDescription.vue`・`NewBrandProp.js`・`Detail/CategoryEdit.vue`)と、本番の画面のビルド(`production-public/6.js`。候補の部分はソースと同じ)を読んで書いた。旧システムを動かして確かめてはいない。

- 候補が 0 件のとき: 旧は、選べる銘柄が 0 件でも「(新しく作成する)」だけの選択の欄を出した(選択の欄を出さずに「-有名な銘柄を入力して下さい-」と出したのは、カテゴリの新規だけ。ミドルの新規・銘柄の無いカテゴリやミドルの編集では選択の欄を出した) → 新は候補が 0 件なら、どの深さのノードでも選択の欄を出さず「-有名な銘柄を入力して下さい-」と出す(決まったこと 2。#309 のやること 1)
- 欄の名前: 旧のその場で作る銘柄の欄は「Name」「%」「Youtube」「画像ファイルをアップロードしてください」 → 新は「英名」「度数(%)」「YouTube」「画像」(決まったこと 3。銘柄のフォームと同じ)
- 度数の欄の長さ: 旧は 4 文字の目安(`counter`)を出すだけで、5 文字目からも入った → 新は 4 文字で止める(決まったこと 3。銘柄のフォームと同じ。#309 のやること 2)
- メジャー・お気に入り: 旧は押すと必ず「入れる」になり、外せなかった(`$emit('update:is_major', !!$event)` の旧の不具合) → 新は押すたびに入れ・外しができる(決まったこと 3。銘柄のフォームと同じ)
- 重なりの知らせの出し方: 旧はその場で作る銘柄の名前・英名の欄の下に「[Warn]同じ名前が存在しています」を出し、欄も赤い誤りの見た目にした → 新は欄の下に「同じ名前が存在しています」(API の文。#632)を出し、欄は誤りの印にしない(決まったこと 3。銘柄のフォームと同じ。保存を止めない知らせを、送れない誤りと見分けられるようにするため)
- 英名の重なりの問い合わせ: 旧は半角にする前の入れた値で問い合わせた(全角で入れると、半角で保存する値がほかの銘柄と重なっても出なかった) → 新は半角にした値で問い合わせる(決まったこと 3。銘柄のフォームと同じ。保存する値で比べるため)
- 空にしたときの重なりの知らせ: 旧は問い合わせず、前に出ていた知らせを残した → 新は問い合わせず、知らせを消す(決まったこと 3。銘柄のフォームと同じ。空の欄は重ならないため)
- 選び直して戻したときの重なりの知らせ: 旧は既存の銘柄を選ぶとその場で作る銘柄の欄を作り直したので、「(新しく作成する)」に戻すと、名前・英名は残るのに知らせは消え、値を変えて離れ直すまで出なかった → 新は名前・英名とともに知らせも残す(決まったこと 3。欄に残っている値が重なっていることを伝えるため)

送る前の画面での必須の確かめ(旧は有名な銘柄も画面で確かめた)は `docs/decisions/admin-category-form.md` の「旧との差分」、候補の範囲(旧のミドルは親のカテゴリの直下の銘柄も選べた)は `docs/decisions/strength.md` の「旧との差分」、その場で作る銘柄の YouTube とリンク(旧はノードの YouTube を入れ、リンクを保存しなかった)は #121 の本文の「旧との差分」にある。
