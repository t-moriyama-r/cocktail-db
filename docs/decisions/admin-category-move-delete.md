# 管理画面のノードの親の付け替えと削除

#125 で作った画面の決まり。仕様は #125 の本文(オーナーが旧の画面で確かめて書いた「追記: 旧の画面で確かめた仕様」)のとおり。ここは、テストの表から指せる「旧との差分」の節にまとめ、画面を作るときに決めた細かいところを足したもの。付け替えの API(自分の下へは移せない・有名な銘柄が部分木の外になるなら 422)は #122、削除の API(消せない理由の 409・`delete_blockers`)は #121 にある。

## 決まったこと

1. 付け替えと削除は、ノードの編集画面(`/admin/categories/<ID>`。#308)の、子のノード・直下の銘柄の一覧の下に、「親の付け替え」「ノードの削除」の欄として出す
2. 親の付け替えの欄は、根でないノードにだけ出す。根を別のノードの下へ移すか・根にするかは、根の役割(#310)と関わるので、ここでは作らない
   - 今の親(根から親までの名前)を出し、「移す先を選ぶ」を押すと、管理 API の木(`GET /api/admin/categories`)を読み込んで出す。編集のたびに大きな木を出さない・読み込まないよう、ふだんは閉じておく
   - 木から移す先を 1 つ選ぶ。自分・自分の下のノード・今の親は選べない
   - 移す先の根の役割が今と違うときは、選んだところに「役割が〈なし〉から〈その他〉に変わります」のように出す(役割の名前はカテゴリ木の画面と同じ「なし」「ソフトドリンク」「その他」)。役割で、有名な銘柄が必須か任意か・材料の数・量の出し方(「1 → 1個」)が変わるため
   - 「移す」を押すと、「「<名前>」を「<移す先の根から親まで>」の下へ移します。<役割が変わるならその文>。よろしいですか?」で確かめてから送る
   - 送るのは、開いたときのノードの値(`PUT /api/admin/categories/{id}` の全項目)に新しい親を入れたもの。上のフォームで書き換えて保存していない値は送らない
   - 移せないとき(422)は、API が返す理由(自分の下へは移せない・下の銘柄が祖先の有名な銘柄になっている、など)を、欄の下にそのまま出し、画面に残る。422 以外の失敗はエラーの番号を出す
   - 移せたら、カテゴリ木の画面へ戻り、「「<名前>」を「<移す先>」の下へ移しました」を出す(保存の後の警告があれば続ける)
3. 削除の欄は、どのノードにも出す
   - 開いたときの応答の `delete_blockers` があれば、「このノードは消せません」と理由(子・銘柄・材料・ベース・アフィリエイト)をすべて出し、消すボタンを押せなくする
   - 消せるノードは「消すと元に戻せません。」と出し、「このノードを消す」を押すと「「<名前>」を消します。よろしいですか?」で確かめてから消す(用語の削除と同じ確かめ方)
   - 開いた後にほかで増えて 409 になったときは、応答の理由をそのまま出し、消すボタンを押せなくする
   - 消せたら、カテゴリ木の画面へ戻り、「「<名前>」を消しました」を出す

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-category-move-delete.md)` としてここを指す。旧の挙動は #125 の本文の追記(旧の画面で確かめたもの)による。

- 付け替えの操作: 旧はミドルの編集で親カテゴリを選び直すか、カテゴリの編集で「種類」(種別)を変えて保存した → 新は編集画面の「親の付け替え」の欄で、木から移す先を選んで移す(決まったこと 2)
- 根をまたぐ付け替えの確かめ: 旧は確かめずに、保存するとそのまま種類(役割)が変わった → 新は役割が変わることを出し、確かめてから移す(決まったこと 2)
- 移せないとき: 旧は元の親の有名な銘柄が移すミドルの中の銘柄だと、500 と「このミドルカテゴリ内の「〈銘柄〉」が「〈カテゴリ〉」の有名な銘柄として含まれてしまっています。」を返し、画面には出なかった → 新は API の理由(422)を欄の下に出し、画面に残る(決まったこと 2)

削除は旧に無い(テストの表では `旧に無い`)。
