# トップのカクテルの件数・一覧・新着動画の API

#39 で決めたこと。公開の `GET /api/cocktails/count`(件数)・`GET /api/cocktails?sort=recent|recommend|random&limit=N`(最近・おすすめ・ランダム)・`GET /api/cocktails/latest-video`(新着動画)の決まり。元は旧 `CommonController` の `countCocktail`・`cocktailRecent`・`cocktailRecommend`・`cocktailRandom`・`getNewMovie`(本番の `laravel13`)。

## 決まったこと

1. **下書きはどれにも出さない**(旧と同じ。旧も `is_draft = 0` で絞っていた)。件数も下書きを数えない
2. **最近は、更新日時(`updated_at`)の新しい順**(旧と同じ)。同じ日時なら ID の大きい順にして、並びを決める
3. **おすすめは、評価(`rate`)が 3 以上のカクテルからランダムに選ぶ**(旧 `cocktailRecommend` と同じ。`is_major` ではない。#39 の追記)。評価の無いカクテルは選ばない
4. **ランダムは、すべての公開のカクテルからランダムに選ぶ**(旧と同じ)
5. **件数(`limit`)は 1〜50 の整数。省くと 10**。外れた値・並べ方(`sort`)の無い・知らない値は 422
6. **一覧の 1 件は、カクテルの表(#298)の 1 行の形**。同じ名前の一覧(`GET /api/cocktails/{id}/same-name`)と同じ項目に、技法の英名を足したもの(#39 の追記)
7. **新着動画は、動画(`youtube`)のある公開のカクテルのうち、動画の公開日時(`youtube_created_at`)がいちばん新しいもの**。同じ日時なら ID の大きいもの。動画のある公開のカクテルが無ければ 404
8. **新着動画は、ID・名前・英名・動画の ID・動画の公開日時・ベース・説明文を返す**。説明文は区切りの並び(#286。`docs/decisions/description-segments.md`)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/cocktail-lists.md)` としてここを指す。旧の結果は本番の `laravel13` のソースから読んだもの(旧システムを動かして確かめてはいない)。

- 件数の上限: 旧は件数をパス(`/api/CocktailRecent/{count}`)で受け、上限が無かった(大きな数を送るとその件数まで返す) → 新は `limit` で受け、1〜50 の外は 422(決まったこと 5。#39 の「やること」)
- 件数が整数でないとき: 旧はパスの数を `int` で受けるので、数でない値は型のエラー(500)になる → 新は 422(決まったこと 5)
- 一覧の 1 件の形: 旧は詳細と同じ形(`CocktailResourceForDetail`。材料が無く、表の「ベース」「必須」が空だった) → 新は表の 1 行の形(決まったこと 6。#39 の追記)
- 最近の、更新日時が同じカクテルの並び: 旧は決めていない(DB の返した順) → 新は ID の大きい順(決まったこと 2)
- 新着動画の、動画の無いカクテル: 旧は動画の有無を見ずに `cc_youtube_created_at` の新しい順の先頭を返した(動画のある公開のカクテルが無ければ、動画の無いカクテルを返す。旧の本番のデータには動画のあるカクテルがあるので、画面で起きたことは無い) → 新は動画のあるカクテルだけから選び、無ければ 404(決まったこと 7)
- 新着動画の形: 旧は詳細と同じ形(`CocktailResourceForDetail`) → 新はトップの動画の枠に出す項目だけ(決まったこと 8。#39 の追記)

応答の包み方(旧の `{"result": {"count": …}}`・`{"result": {"cocktail": …}}` → 新の `{"count": …}`・`{"data": …}`)は、新しい画面に合わせて変えた。表示する中身は変えていない。
