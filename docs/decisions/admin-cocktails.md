# 管理画面のカクテルの新規・編集(基本情報・材料の行)

#127(基本情報)と #128(材料の行)で決めたこと。決めたのは #127 の本文の「追記: 旧の画面で確かめた仕様」「追記: #126 から回したこと」と、#128 の本文の「追記: 旧の画面で確かめた仕様」「追記: #127 から回したこと」(オーナーが書いた)で、ここはそれを、テストの表から指せる「旧との差分」の節にまとめ、画面を作るときに決めた細かいところを足したもの。API(検証・下書きの決め方)は #291、材料の保存の API は #292 で、その差分はそれぞれの本文の「旧との差分」にある。行の足し・消し・並べ替えと行の上限は `docs/decisions/admin-screens.md` の決まったこと 5。別名の欄(決まったこと 12)は #83 で足した(API は #293)。

## 決まったこと

1. 新規は、カクテルの一覧(`/admin/cocktails`)の上の「新規」のリンク(`/admin/cocktails/new`)から、編集は一覧の 1 行(`/admin/cocktails/<ID>`)から開く(銘柄の一覧と同じ形。`docs/decisions/admin-layout.md` の 3)
2. フォームの並びは、旧と同じく、(同じ名前のカクテルがあれば左に一覧)/ ベース / 氷の有無・グラス / 名前・英名 / 意味検索・カクテル言葉検索のリンク / 製法・評価・甘さ・メジャー / 説明 / 補足 / YouTube と開始位置 / 画像 / リンクテキスト・リンクURL / 材料 / 保存・削除。旧に無い別名の欄(決まったこと 12)は、検索のリンクと製法のあいだに置く
   - 欄の名前は、旧の「Name」「Youtube」「画像ファイルをアップロードしてください」を、銘柄の画面(`docs/decisions/admin-brands.md` の 3)と同じく「英名」「YouTube」「画像」にする
   - 意味検索は「<英名> 意味」、カクテル言葉検索は「<名前> カクテル言葉」を Google で調べるリンクで、別のタブで開く(旧と同じ)
3. ベースは木の部品(#297)の単一選択で、根の下のどの深さのノードでも選べる。根は見出しにして選べなくする(#153)。選んでいるベースを、根を除いたパンくずで木の上に出す。木は検索フォームの API(`GET /api/search-form`)の木を使う
4. 選択肢は、製法(技法)・グラス・氷は `GET /api/admin/cocktail-form-options`、評価は空・5〜1、甘さは空・-10〜10 の 21 段(旧と同じ)。製法は空の選択肢を置かない(新規のまだ選んでいないあいだだけ、選べない「(選んでください)」を出す)。グラス・氷・評価・甘さは、旧と同じく文字の無い空の選択肢を先頭に置く
5. 開始位置は数字だけを、時は 1 桁、分・秒は 2 桁まで受け付ける。英名は欄を離れたときに全角の英数字を半角にする(旧と同じ。銘柄の画面と同じ部品の関数を使う)。メジャーは、押すたびに入れ・外しができる普通のチェックボックスにする
6. 保存のボタンは「下書きとして保存」「公開する」の 2 つ(`docs/decisions/admin-screens.md` の 1)。Enter で送ったときは、先頭の「下書きとして保存」で送る(誤って公開しないため)。保存できたら、下書きなら下書きの一覧(`/admin/cocktails?status=draft`)へ、公開なら公開済みの一覧へ戻る
7. 検証は API に任せ、送る前に画面では確かめない(材料の行の 2 つの確かめだけは例外。決まったこと 10)。422 は項目ごとに欄の下に出し、材料の行のメッセージ(`ingredients.<行>.<項目>`)はその行の欄の下に、行に付かない材料のメッセージ(`ingredients`。材料の件数・度数を計算できない材料の組など)は材料の欄の上に、別名のメッセージ(`aliases.<行>`)はその行の欄の下に(行に当たらない `aliases` などは別名の欄の下に)、欄の無い項目(下書きなど)のメッセージは保存のボタンの下にまとめて出す。画面を移らず、入力は残す(`docs/decisions/admin-screens.md` の既定)
8. 削除は、編集の画面にだけ出し、確かめてから消す(`docs/decisions/admin-screens.md` の既定)。消せたら、旧と同じくメニュー(`/admin`)へ移る。ほかの説明文から参照されていて消せない(409。#579)ときは、理由と参照している行の名前を出して画面に残る
9. 同じ名前のカクテル(旧の重複チェック。#129 の `same_name`)は、名前・英名を変えるたびに問い合わせ直し(入れている途中は 300ms 待ってから)、編集では開いたときにも問い合わせて、フォームの左に出す。1 件ごとに、製法・名前(そのカクテルの編集画面へのリンク)・材料の行(ノード・銘柄・量)・説明・補足を出す。保存は止めない
   - 同じレシピのカクテル(#129 の `same_recipe`。`docs/decisions/admin-screens.md` の決まったこと 3。「決まったことに書かれていないこと」の「同じレシピの警告をどの画面に出すか」)は、同じ左の欄に、名前の一覧の下に「同じレシピのカクテル」の見出しを分けて出す。どちらの一覧も、0 件なら見出しごと出さない
   - md(960px)以上の幅では左に並べ、それより狭い幅ではフォームの上に、高さを抑えて出す
10. 材料は、行を足す・消す・上下に並べ替えるができる(#128。`docs/decisions/admin-screens.md` の決まったこと 5)。並びがそのままレシピの順になる
   - 新規は、空の行を 2 つ(保存に要る件数)出す。編集は、今の材料を並びのまま出す。「行を足す」で末尾に足し、20 行になると足せない。行はどれも消せる(2 行を切ると、保存のときに API が件数の 422 を返す)
   - 1 行の欄は、ノード・銘柄・量・任意(旧と同じ)。ノードは木の部品(#297)の単一選択で、根の下のどの深さからも選ぶ(根は選べない。#153)。木は行の「ノードを選ぶ」で開き、選ぶと閉じる。開くのは 1 行だけにする(20 行の木が並ぶと画面が埋まるため)。選んでいるノードを、根を除いたパンくずで出す
   - 銘柄の選択肢は、行のノードとその配下すべての銘柄(ノードの詳細の API `GET /api/categories/{id}` の `brands`)を、旧と同じく「名前(英名)」で出す。ノードを選ぶまでは選べない。銘柄を選ぶと、ノードは銘柄の所属ノードになる(#19)。ノードを選び直すと銘柄を空にする(旧と同じ)。今の銘柄が行のノードの配下に無い(移した旧データの、ノードと銘柄の所属が合わない行など)ときは、「(このノードの配下に無い銘柄)」の選択肢で出し、保存すると API の 422 で知らせる
   - ベースと 1 行目: ベースが空のときに、空の 1 行目のノード(銘柄)を選ぶとベースにも入れ、ベースを空から選ぶと空の 1 行目にも入れる(旧と同じ。#127 の追記)。入れるのは空の側にだけで、もう選んである側は変えない
   - ノードを選んでいない行も、飛ばさずに並びのまま送る(API の 422 の「材料 N 行目」が画面の行の番号と合うように)。行が 1 つも無いときは、空の `ingredients` を送る(更新で送らないと今の材料が残るため。#720)
   - 送る前に、旧と同じ 2 つを画面で確かめ、当たれば送らずに、旧と同じ文言を材料の欄に出す(どちらも API は確かめないため): 同じノード・同じ銘柄(どちらも銘柄なしを含む)の行が 2 つあると「レシピが重複しています！」、ベースがどの行のノードとも同じでなく、どの行のノードの祖先でもなければ「ベースが見つかりません！」。ノードを選んでいない行は数えない。ベースが空のときと、ノードのある行が無いときは、ベースを確かめない(必須の入れ忘れを API の 422 で先に見せるため)
   - 422 の行のメッセージは、送ったときの行に付け、並べ替えても行に付いたまま動く。行の欄を直すと、その欄のメッセージと材料の欄の上のメッセージを外す
11. お気に入り(`is_like`)は出さない(旧と同じ)。度数・材料の数は入力しない(保存のときに API が計算する)
12. 別名(#83。旧に無い)は、別名ごとに「別名 <番号>」の欄と「削除」を 1 行に並べ、「別名を足す」で空の行を足す。別名が無ければ「別名はありません。」と出す。保存のときは、欄の並びのまま送って置き換える(1 つも無ければ全部消す)。欄の文字は整えず、空の行も送って API の 422 に任せる(決まったこと 7)
   - 検索用の名前が同じ別名・カクテルの名前と同じ別名は、API が 422 にする(#293)。その行の欄の下に出す。欄を直すとその行のメッセージを、行を足す・消すと(行の番号がずれるので)別名のメッセージをすべて外す
   - ほかのカクテルの名前・別名と同じ別名は、保存したうえで API が `warnings` に入れて返す(#293)。編集画面はそのまま一覧へ戻り(決まったこと 6)、戻った一覧の上に、どの別名がどのカクテルと同じかと、そのカクテルの編集画面へのリンクを出す(カテゴリ木の画面の保存の後の知らせ(`docs/decisions/admin-category-form.md`)と同じく、履歴の state で持たせる)。`warnings` が空なら何も出さない
   - 保存を待つあいだは、行を足す・消すを押せない(返ってきたメッセージの行の番号が、画面の行とずれないように)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-cocktails.md)` としてここを指す。旧の画面のソース(cocktail-legacy の `laravel6/resources/js/Admin/Super/Detail/CocktailEdit.vue`・`component/NamesAndDescription.vue`・`component/AutoInputDub.vue`・`component/RecipeList.vue`・`component/RecipeSelect.vue`・`component/CategorySelect.vue`)と、旧の BE(`laravel13` の `RecipeFactory::saveRecipe`)を読んで書いた。旧システムを動かして確かめてはいない(旧の管理画面は Twitter の OAuth でしかログインできず、手元で動かす旧システムでは開けない)。

- 新規の入口: 旧はメニューの「カクテル新規」から開いた → 新はカクテルの一覧の上の「新規」のリンクから開く(決まったこと 1。#126 から回したこと)
- 欄の名前: 旧は「Name」「Youtube」「画像ファイルをアップロードしてください」 → 新は「英名」「YouTube」「画像」(決まったこと 2)
- 製法・グラスの選択肢の文字: 旧は「名前(英名)」 → 新は名前だけ(選択肢の API(#291)が名前だけを返すため)
- 製法の空の選択肢: 旧は新規の画面で製法が空のまま出た(空の選択肢は無く、選び直すと空には戻せない) → 新は、まだ選んでいないあいだだけ選べない「(選んでください)」を出す(決まったこと 4。HTML の選択の欄は、選択肢に無い値を空のまま出せないため)
- メジャー: 旧は押したときに `$emit('update:is_major', !!$event)` で、イベントを真偽値にしていたため、押すと必ず「入れる」になり、外せなかった(旧の不具合) → 新は押すたびに入れ・外しができる(決まったこと 5。銘柄の画面(`docs/decisions/admin-brands.md`)と同じく直した)
- 送る前の確かめ: 旧は送る前に、画面で必須(ベース・名前・英名・製法と、材料の 1・2 行目のカテゴリ・カテゴリのある行の量)を確かめ、足りなければ送らなかった → 新は画面では確かめずに送り、API の 422 を項目ごとに出す(決まったこと 7。材料の行の 2 つの確かめ(レシピの重複・ベースが材料に無い)は旧と同じく送る前に画面で確かめる。決まったこと 10)
- 保存のボタンを Enter で押したとき: 旧はボタンが「送信」1 つだった → 新は先頭の「下書きとして保存」で送る(決まったこと 6)
- 同じレシピのカクテルの出し方: 旧には同じレシピの一覧が無かった → 新は左の欄の、名前の一覧の下に見出しを分けて出す(決まったこと 9。出すことそのものは `docs/decisions/admin-screens.md` の 3)
- 同じ名前のカクテルの製法: 旧は製法をアイコン(1〜6 の技法ごとの絵)で出した → 新は製法の名前で出す(技法は旧の 6 つに決まっておらず、`methods` の行ごとの絵が無いため)
- 名前・英名の欄の下の警告: 旧は欄を変えると、表の全体で同じ名前(英名)があるかを別に問い合わせ(`duplicate_check`)、欄の下に「[Warn]同じ名前が存在しています」も出した(編集しているカクテル自身にも当たった) → 新は欄の下には出さず、左の同じ名前の一覧だけで知らせる(決まったこと 9。#127 の本文の追記が左の一覧だけを挙げているため。重なりは左の一覧にすべて出る)
- 名前・英名を空にしたとき: 旧は空にしても問い合わせ直さず、前の一覧を出したままにした → 新は名前・英名がどちらも空なら一覧を消す(API は名前・英名のどちらかが要るため)
- 同じ名前の一覧の置き方: 旧は画面の左半分に固定して出した(狭い幅でもフォームと半分ずつ) → 新は md(960px)以上の幅で左に並べ、それより狭い幅ではフォームの上に高さを抑えて出す(決まったこと 9。狭い幅で入力の欄が半分の幅にならないように)
- 削除できないとき: 旧は削除の結果を待たずにメニューへ移った → 新は 409 なら理由と参照している行を出して画面に残る(決まったこと 8。参照の確かめそのものは #579)
- 最初に出す材料の行の数: 旧は今の材料に空の行を足して 12 行の枠で出した(新規は 12 行とも空) → 新は、新規は空の行を 2 つ、編集は今の材料の行だけを出し、要るだけ足す(決まったこと 10。行を足せるので、空の枠を並べておかなくてよいため)
- 材料のノードの選び方: 旧はカテゴリ・ミドルカテゴリ・銘柄の 3 つの選択の欄と、頭文字で絞る欄で選んだ → 新はノードを木(#297)で根の下のどの深さからも選び、銘柄は別の選択の欄で選ぶ(決まったこと 10。材料のノードを任意の深さにしたこと(#292 の「旧との差分」)に合わせる)
- 銘柄の選択肢: 旧はカテゴリを選ぶ前でも、頭文字の欄で全部の銘柄から絞って選べた(選ぶとカテゴリ・ミドルが入った) → 新はノードを選んでから、そのノードと配下の銘柄から選ぶ(決まったこと 10。銘柄は数が多く、木でノードを選べばそこから絞れるため)
- 行のノードの配下に無い今の銘柄: 旧は銘柄の欄を空のように出した(選択肢に無いため。保存ではその銘柄をそのまま送った) → 新は「(このノードの配下に無い銘柄)」の選択肢で出し、保存すると API が 422 を返す(決まったこと 10。所属の合わない行を、空と見分けて直せるように。422 にするのは #292 の「旧との差分」)
- ノードを選んでいない行: 旧は保存のときに飛ばした(BE の `saveRecipe` がカテゴリの無い行を入れなかった。量だけを入れた行も黙って消えた) → 新は飛ばさずに送り、API が「材料 N 行目のノード」の 422 を返す(決まったこと 10。旧は 12 行の空の枠を飛ばす必要があったが、新は要らない行を消せる。量だけを入れてノードを入れ忘れた行を、黙って消さずに知らせるため)
- レシピの重複・ベースが材料に無いときの出し方: 旧は `alert` で出した → 新は材料の欄に出し、保存のボタンの下に「保存できませんでした。入力を確かめてください。」を出す(決まったこと 10。ほかの誤りと同じ出し方にそろえる)
- 確かめる順: 旧は必須(ベース・材料の 1・2 行目のカテゴリと量など)を先に確かめ、通ってからレシピの重複・ベースが材料にあるかを確かめた → 新は必須を API の 422 で出すので、レシピの重複・ベースを先に画面で確かめ、通ってから送る。重複に当たると、必須の入れ忘れはその後の送信で出る(決まったこと 7・10)
- ベースが材料にあるかの比べ方: 旧はベースと、材料の行の 2 段目のカテゴリが同じかで比べた → 新は材料のノードがベースそのものか配下かで比べる(決まったこと 10。ベース・材料のノードを任意の深さにしたため(#291・#292 の「旧との差分」)。ベースが「ジン」で材料が「ドライジン」の銘柄なら、ベースは材料にある)
- ベースを空から選んだときの 1 行目: 旧は 1 行目にもうカテゴリが入っていても上書きした(ベースの頭文字の欄に打つとベースが空に戻り、選び直すと 1 行目のカテゴリが変わった。ミドル・銘柄はそのまま残った) → 新は 1 行目が空のときだけ入れる(決まったこと 10。選んである材料を黙って変えないため。新はベースを空に戻せないので、この形になるのは 2 行目以下の行を 1 行目へ動かしたときなど)

別名の欄(決まったこと 12)は旧に無いので、ここには差分として挙げない。

保存のボタン・保存に失敗したときの出し方・削除の確かめ・材料の行の上限と並べ替えは `docs/decisions/admin-screens.md` の「旧との差分」、ベースを任意の深さのノード 1 つで選ぶこと(旧は 2 段目のカテゴリだけ)・検証の差は #291 の「旧との差分」、材料のノード・銘柄と所属ノードの検証の差は #292 の「旧との差分」にある。
