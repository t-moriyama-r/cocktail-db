# 管理画面の言い換え辞書・スキップ語

#67 で決めたこと。決めたのは #67 の本文の「追記: 旧の画面で確かめた仕様」(オーナーが書いた)で、ここはそれを、テストの表から指せる「旧との差分」の節にまとめたもの。相手の API は #316(読み替え先の解決の決まりは `docs/decisions/paraphrase-target.md`)。

## 決まったこと

1. 画面は `/admin/paraphrases` の 1 つで、メニューの「言い換え・スキップ語」で開く(`docs/decisions/admin-layout.md` の 2 の並び)。言い換え辞書とスキップ語の、2 つの一覧(一覧の部品 #120)とフォームを上下に並べる
2. どちらも、一覧の 1 行を押すとフォームに読み込み(旧の言い換えの画面と同じ)、保存(足す・書き換える)・削除ができる。保存に失敗したら欄ごとに誤りを出して入力を残し、削除は確かめてから消す(`docs/decisions/admin-screens.md` の既定)
3. 言い換えのフォームは、旧と同じく変換前・command(「(未選択)」「強制ホット」)・note と、変換後・ミドルの欄。変換後は、木の部品(#297)でノードか、選んだノードの配下の銘柄を選ぶと名前が入る。名前を手で入れてもよい(表は名前のまま持つ。#33)。解決できない名前は、API の 422(#316)を欄の下に出す
   - 根のすぐ下のノード(旧のカテゴリ)を選ぶと、変換後にその名前、ミドルは空
   - それより深いノード(旧のミドル)を選ぶと、変換後に根のすぐ下の祖先の名前、ミドルにそのノードの名前(旧の画面もカテゴリとミドルを分けて選んだ。ミドルを空にすると、同じ名前の銘柄があればそちらに解決されるため)
   - 銘柄を選ぶと、変換後に銘柄の名前、ミドルは空(銘柄はミドルを持てない)
   - 根(旧の種別)は読み替え先にできない(API が根を探さない)ので、木では見出しにして選べなくする
4. 言い換えの一覧の 1 行は、旧と同じ「〈変換前〉 → 〈変換後〉 【〈ミドル〉】」と note の印に、解決した先のパンくずを足す(根からのノードの名前と、銘柄ならその名前)。解決できない語は、そう出す

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-paraphrases.md)` としてここを指す。旧の挙動は本番の画面の Vue のソース(`laravel6/resources/js/Admin/Super/ParaPhraseList.vue`・`ListComponent.vue`)から読み取ったもので、旧を動かして確かめてはいない。旧に保存のボタンもスキップ語の画面も無かったので、保存・削除・スキップ語の画面そのものは差分ではなく「旧に無い」。

- 一覧の行: 旧は「〈変換前〉 → 〈変換後〉 【〈ミドル〉】」と note の印だけ → 新はその後ろに、解決した先のパンくず(解決できなければ「解決できません」)を出す
- 一覧の絞り込み: 旧は変換前の前方一致(画面で絞った) → 新は変換前・変換後・ミドルの部分一致(API の `q`。#316)
- 一覧のページング: 旧は全件を 1 枚に出した → 新は 50 件ずつ(`docs/decisions/admin-screens.md` の 6 と同じ)
- 変換後の選び方: 旧はカテゴリ・ミドル・銘柄を選ぶ欄(`RecipeSelect`) → 新は木から選ぶか、名前を手で入れる
