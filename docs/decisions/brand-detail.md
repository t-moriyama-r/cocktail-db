# 銘柄の詳細の API

#43 で決めたこと。公開の `GET /api/brands/{id}`(銘柄の詳細)の決まり。画面は #54 で作る。

## 決まったこと

1. **銘柄の位置は、所属ノードの根からのパンくず(`path`)で返す**。根(大元)が先頭で、所属ノードが末尾(`CategoryTree::path`)。旧はカテゴリ・ミドル・種別を別の項目(`category`・`middle`・`kind`)で返していた。カクテルの詳細の材料(`docs/decisions/cocktail-detail.md` の決まったこと 4)と同じ形にそろえた
2. **銘柄の一覧は 2 つ返す**(`docs/decisions/public-detail.md` の決まったこと 2)。どちらも ID の順
   - `same_node_brands`: 所属ノードに直接ぶら下がる、ほかの銘柄(自分を除く)。旧の「同じミドルのほかの銘柄」(`brands_belong_middle`)にあたる
   - `parent_subtree_brands`: 所属ノードの親と、親の配下すべてのノードのうち、所属ノードでないノードに所属する銘柄。旧の「同じカテゴリで別のミドルの銘柄」(`brands_belong_category_except_middle`)にあたる。所属ノードが根なら親が無いので空の並び
   - 一覧の 1 件は、名前・英名・度数(`strength`)・動画(`youtube`)と、所属ノードの根からのパンくず(`path`)
3. **「これを使ったカクテル」は返さない**。画面が #174 の銘柄起点の API で取る(#43 の追記。銘柄を指定した材料に加えて、同じノードで銘柄を指定していない材料も当たる)
4. **アフィリエイトは返さない**。画面が `GET /api/affiliates`(#47)にノードと銘柄の ID を渡して取る
5. **説明文は、文字とリンクの区切りの並びで返す**(#286。`docs/decisions/description-segments.md`)
6. **無い銘柄の ID は 404**。数字でない ID・int に収まらない桁数の ID も、経路に合わずに 404(カクテル・用語の詳細と同じ)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/brand-detail.md)` としてここを指す。旧システムは手元で動かしていない(旧の挙動は、cocktail-legacy の `laravel13/app/Http/Controllers/DetailController.php` の `brand` と `BrandFactory` を読んだもの)。

- 無い ID: 旧は `abort(500)` で 500 → 新は 404(決まったこと 6。カクテルの詳細(`docs/decisions/cocktail-detail.md`)・用語の詳細・アフィリエイト(`docs/decisions/affiliate-api.md`)と同じ扱い)
- 銘柄の位置: 旧はカテゴリ・ミドル・種別を別の項目で返していた → 新は所属ノードの根からのパンくずで返す(決まったこと 1)
- 一覧の銘柄の所属: 旧は銘柄ごとにカテゴリ・ミドルの 2 段を別の項目で返していた → 新は所属ノードの根からのパンくずで返す(決まったこと 2)
- 銘柄の一覧の並び: 旧は `ORDER BY` を付けずに引いていた(並びは DB に任せていた) → 新は ID の順に決める(決まったこと 2)
- 同じノードのほかの銘柄が無いとき: 旧はミドルの無い銘柄で `brands_belong_middle` を null にしていた → 新はいつも並びで返し、無ければ空の並び(決まったこと 2。旧の画面は null と 0 件のどちらでも欄を出さないので、画面に出るものは変わらない)

応答の項目の名前と形(`brandDetail` → 応答の直下、YouTube の開始位置の `y_h`・`y_m`・`y_s` → `youtube_start_seconds`、画像の `image` を `asset()` の URL ではなく保存した値のまま返す(カクテルの詳細と同じ)など)は、新しい画面(#54)に合わせて変えた。表示する中身は変えていない。

## 決まったことに書かれていないこと

`docs/decisions/public-detail.md` の決まったこと 2 の言葉どおりに作った。次の 3 つは、旧と違う結果になるか、旧に無い場面で、オーナーの判断を待っている(#43 の PR のコメント)。決まったら、ここと `parent_subtree_brands` の選び方を直す。

- **親ノードに直接ぶら下がる銘柄**: いまは入れている(親ノード自身も「別のノード」)。旧は、ミドルのある銘柄の詳細では、カテゴリの直下(ミドルなし)の銘柄を入れていなかった(`getFromCategoryExceptMiddle` の `middle_category <> ?` が NULL に当たらないため)
- **いちばん上の段(旧のカテゴリ)に所属する銘柄**: 旧のミドルの無い銘柄は、移行でいちばん上の段のノードに所属する。その親は大元(旧の種別)なので、いまは大元の配下のほかのノード(ラムの銘柄なら、ホワイトラムの銘柄に加えてジン・ウォッカなどの銘柄)がすべて入る。旧は、同じカテゴリのほかの銘柄(配下のミドルの銘柄を含む)だけを出していた
- **所属ノードの子孫のノードの銘柄**: いまは `parent_subtree_brands` に入れている(所属ノードでない「別のノード」)。旧はミドルの下に段が無かったので、旧に無い場面
