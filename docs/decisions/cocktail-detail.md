# カクテルの詳細の API

#40 で決めたこと。公開の `GET /api/cocktails/{id}`(詳細)・`GET /api/cocktails/{id}/same-name`(同じ名前の別のカクテル)と、管理者が下書きを見る `GET /api/admin/cocktails/{id}/preview` の決まり。

## 決まったこと

1. **下書きは公開の API に出さない**。下書きを指定したら 404。同じ名前の一覧にも下書きを入れない(#40 の本文と追記)
2. **管理者が下書きを見るときは、管理 API の `GET /api/admin/cocktails/{id}/preview`**。公開の詳細と同じ形で、下書きも返す。公開の API はセッションを使わない(`bootstrap/app.php`。#118)ので、ログインしているかで公開の API の返すものを変えられない。公開の API にセッションを通すと、ログインしていない人の応答にもセッションのクッキーが付くので、管理 API に分けた
3. **技法から、それを説明する用語へのリンクは、`methods.dictionary_id` に持つ**(`docs/schema.md` の「`methods`」)。旧は技法の ID と用語の ID がたまたま同じ(1〜6)ことに頼っていた。移行では、技法と同じ名前の用語を結び付ける(旧の本番のデータでは 6 つとも同じ名前の用語がある)
4. **材料のノードは、根からのパンくずで返す**。旧はカテゴリ・ミドルの 2 段を別の項目で返していた。新は木の深さが決まっていないので、根から材料のノードまでの全段を返す。どの段を画面に出すかは画面が決める(#283 の 3。いちばん上の段と材料のノードだけを出す。`docs/decisions/public-detail.md`)
5. **「同じ名前」は英名(`name_eng`)が同じもの**(旧 `CocktailFactory::sameName` と同じ)。英名の無い(null・空の)カクテルは 0 件
6. **説明文・補足は、文字とリンクの区切りの並びで返す**(#286。並びの形と旧との差分は `docs/decisions/description-segments.md`)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/cocktail-detail.md)` としてここを指す。旧での結果は、旧システムを手元で動かし(`docs/legacy-local.md`)、旧の `cocktailDetail`・`getSameNameCocktail` の API に同じ ID を送って確かめた。

- 下書きの詳細: 旧は誰にでも 200 で中身を返していた(旧の ID 5554) → 新は公開の API では 404。管理者は管理 API で見る(決まったこと 1・2)
- 無い ID の詳細・同じ名前: 旧は 500(見つからないカクテルで型のエラー) → 新は 404
- 同じ名前の一覧の下書き: 旧は下書きも返していた(旧の ID 6199 を開くと、下書きの 6200 が出た) → 新は返さない(決まったこと 1)
- 下書きを指定した同じ名前: 旧は 200 で一覧を返していた(旧の ID 6200) → 新は 404(決まったこと 1)
- 英名の無い(null・空の)カクテルの同じ名前: 旧のソースでは、英名の無いほかのカクテルをすべて返す(`where("name_eng", null)` が `IS NULL` になる。旧の本番のデータに英名の無いカクテルは無いので、画面で起きたことは無い) → 新は 0 件(決まったこと 5)
- 説明文・補足: 旧はリンクの区切りの並び(`[{txt}, {command, id, txt, is_youtube}]`)で返していた → 新も区切りの並びで返す。並びの形の違いは `docs/decisions/description-segments.md` の「旧との差分」(決まったこと 6)

応答の項目の名前と形(`method` の `method_id` → `id` など、材料の `category`・`middle` → `path`)は、新しい画面(#108・#109)に合わせて変えた。表示する中身は変えていない。
