# 管理画面のノードの新規・編集フォーム(基本の項目)

#308 で作った画面の決まり(根の作成と役割は #310 で足した。決まったこと 9)。項目と検証の扱いは #308 の本文(オーナーが書いた)と、`docs/decisions/admin-screens.md`(#284)の決まったことのとおり。ここは、テストの表から指せる「旧との差分」の節にまとめ、画面を作るときに決めた細かいところを足したもの。保存の API(検証・名前の重なりの 422・保存の後の警告)は #121 で、その差分は #121 の本文の「旧との差分」にある。

有名な銘柄の選択とその場での作成は #309 で足した(`docs/decisions/admin-category-famous-brand.md`)。

## 決まったこと

1. 新規は、カテゴリ木の画面(`/admin/categories`。#123)の上の「新規」のリンク(`/admin/categories/new`)から開く。編集は、カテゴリ木の画面でノードを選ぶと開く(`/admin/categories/<ID>`)。旧のカテゴリとミドルは同じ項目なので、任意の深さのノードを 1 つのフォームで編集する
2. フォームの並びは、旧と同じく、親 / 名前・英名 / メジャー・お気に入り・粉もの / 説明 / YouTube と開始位置 / 画像 / リンクテキスト・リンクURL / 有名な銘柄(#309) / 送信。その下に、子のノードの一覧と直下の銘柄の一覧を出す(旧の「登録されているミドルカテゴリ一覧」「登録されている銘柄の一覧」)。一覧の 1 行は、旧と同じく「名前(英名)」の編集画面へのリンク
   - 欄の名前は、銘柄のフォーム(`docs/decisions/admin-brands.md` の決まったこと 3)と同じく、旧の「Name」「Youtube」「画像ファイルをアップロードしてください」を「英名」「YouTube」「画像」にする
3. 親は、新規なら木の部品(#297)の単一選択で、管理 API の木(`GET /api/admin/categories`)から 1 つ選ぶ。根も選べる。木の上の「親なし(根のノードを作る)」を入れると、木を隠して根を作る(決まったこと 9)。編集では、根から親までのパンくずを出すだけにする。親は編集画面の下の「親の付け替え」の欄(#125)で移す(フォームの親の欄では選び直さない。#675。`docs/decisions/admin-category-move-delete.md`)
4. 説明は、API が返す編集の形(記法に指す先の名前を添えたもの。#287)のまま編集し、そのまま送る
5. 開始位置は数字だけを、時は 1 桁、分・秒は 2 桁まで受け付け、旧と同じく数にして出す。英名は欄を離れたときに全角の英数字を半角にする(銘柄のフォームと同じ)
   - メジャー・お気に入り・粉ものは、押すたびに入れ・外しができる普通のチェックボックスにする
6. 画像は、選ぶとその場で出し、保存で差し替える。今の画像があれば「画像を消す」のチェックで、画像だけを消せる(#288)
7. 検証は API に任せ、送る前に画面では確かめない。保存の 422 は項目ごとに欄の下に出し、画面を移らない(`docs/decisions/admin-screens.md` の既定)。このフォームに欄の無い項目のメッセージは、送信の下にまとめて出す(有名な銘柄の項目の出し方は `docs/decisions/admin-category-famous-brand.md` の決まったこと 5)
   - 名前・英名は、値を変えて欄を離れたら(旧の `@change`)重なりを問い合わせ(`GET /api/admin/categories/duplicates`。#673)、重なれば欄の下に「同じ名前が存在しています」を出す(#674)。知らせるだけで、送信は止めない(名前の重なりは保存の 422 が名前の欄に出し、英名の重なりは保存できて、保存の後の警告が決まったこと 8 のとおり出る)
   - 比べるのは、新規なら選んでいる親の子(「親なし」を入れていれば、前に選んでいた親ではなく根どうし。決まったこと 9)、編集なら今の親の子(根なら根どうし)。編集しているノード自身は `exclude_id` で数えない(#673 の「旧との差分」)。新規で親をまだ選んでいなければ、比べる相手が決まらないので問い合わせない
   - 新規で親を選び直したり、「親なし」を入れたり外したりしたら、前の比べる相手で出した知らせは消す。同じ値のまま欄を離れ直すと、新しい相手で問い合わせる(親を選んだ・「親なし」を入れ外ししただけでは問い合わせない)
   - ほかは銘柄のフォーム(`docs/decisions/admin-brands.md` の決まったこと 8)と同じ。英名は半角にした値で問い合わせ、空にしたら問い合わせずに知らせを消し、知らせは欄の説明にするが欄を検証の誤り(`aria-invalid`・赤い枠)にはせず(誤りの印は保存の 422 で付く)、最後に問い合わせた値の結果だけを出し、問い合わせに失敗したら何も出さない
8. 保存できたら、カテゴリ木の画面へ戻り、「「<名前>」を保存しました」を出す。保存の後の警告(英名が同じ親の下のほかのノードと同じ)があれば、続けて「英名: 同じ名前が存在しています」を出す
9. 根の作成と役割(#310。`docs/decisions/category-root-role.md` の決まったこと)
   - 根は、カテゴリ木の画面の「新規」から開いた新規のフォームで、親の欄の「親なし(根のノードを作る)」を入れて作る。入れているあいだは、親の木と選んでいる親を隠す。外すと、前に選んでいた親のまま木が戻る
   - 役割の欄(なし・ソフトドリンク・その他)は、根のとき(新規で「親なし」を入れた・根の編集)だけ、親の欄の下に出す。根以外では出さず、役割を送らない(役割を持てるのは根だけ)
   - 新規の根の役割は「なし」から始める。「なし」のときは役割を送らない(API は送られない根の役割を null にする)
   - 役割の 422 は、役割の欄の下に出す

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-category-form.md)` としてここを指す。旧の画面のソース(cocktail-legacy の `laravel6/resources/js/Admin/Super/Detail/CategoryEdit.vue`・`MiddleEdit.vue`・`Detail/component/NamesAndDescription.vue`・`KindSelect.vue`・`CategorySelect.vue`、`Admin/Super/BrandList.vue`・`MiddleList.vue`・`ListComponent.vue`)を読んで書いた。旧システムを動かして確かめてはいない。

- 画面の数: 旧はカテゴリ(`CategoryEdit.vue`)とミドル(`MiddleEdit.vue`)で別の画面だった → 新は任意の深さのノードを 1 つのフォームで編集する(決まったこと 1)
- 開き方: 旧はメニューの「カテゴリ新規・編集」「ミドルカテゴリ新規・編集」から、それぞれの一覧を開いて選んだ → 新はカテゴリ木の画面でノードを選ぶと開き、新規は木の上の「新規」から開く(決まったこと 1)
- 親の選び方: 旧はカテゴリなら種別(`KindSelect.vue`)、ミドルならカテゴリ(`CategorySelect.vue`)を選択の欄で選んだ → 新は木から 1 つ選ぶ(決まったこと 3)
- 編集での親の付け替え: 旧のミドルの編集は、所属するカテゴリを選び直して保存できた → 新はフォームの親の欄では親を出すだけで、変えられない(決まったこと 3)。親は編集画面の下の「親の付け替え」の欄(#125)で移す(名前と親を両方変えるときは、保存と「移す」を別々に押す。#675。`docs/decisions/admin-category-move-delete.md`)
- 欄の名前: 旧は「Name」「Youtube」「画像ファイルをアップロードしてください」 → 新は「英名」「YouTube」「画像」(決まったこと 2)
- 子のノードの一覧: 旧はカテゴリの編集だけに「登録されているミドルカテゴリ一覧」があった(ミドルには子が無かった) → 新はどのノードにも「登録されている子のノードの一覧」を出す(決まったこと 2)
- 銘柄の一覧: 旧のカテゴリの編集は、そのカテゴリ(配下のミドルを含む)の銘柄を出した → 新は、そのノードの直下の銘柄だけを出す(#308 のやること 4。下の段の銘柄は、子のノードを開くと出る)
- 銘柄の一覧の 1 行の所属と絞り込み: 旧は一覧の部品(`ListComponent.vue`)が、銘柄の 1 行の後ろに所属(「(★カテゴリ/★ミドル)」)を出し、一覧の上に「絞り込み」の欄を出した → 新は「名前(英名)」だけを出し、絞り込みの欄は出さない(決まったこと 2。どれも開いているノードの直下の銘柄なので所属は同じで、絞り込みは銘柄の一覧の画面(#64)にある)
- メジャー・お気に入り・粉もの: 旧は押したときに `$emit('update:is_major', !!$event)` で、イベントを真偽値にしていたため、押すと必ず「入れる」になり、外せなかった(旧の不具合) → 新は押すたびに入れ・外しができる(決まったこと 5。銘柄のフォームと同じ)
- 画像を消す: 旧は画像を差し替えられるが、消す操作は無かった → 新は「画像を消す」で画像だけを消せる(決まったこと 6。#288)
- 送る前の確かめ: 旧は送る前に、画面で必須(親・名前・英名・説明・有名な銘柄)を確かめ、足りなければ送らなかった → 新は画面では確かめずに送り、API の 422 を項目ごとに出す(決まったこと 7)
- 保存できたとき: 旧は保存の結果によらず(失敗はコンソールに書くだけで)メニュー(`/admin`)へ戻った → 新はカテゴリ木の画面へ戻り、保存したことと保存の後の警告を出す(決まったこと 8。旧のメニューにあったカテゴリ・ミドルの一覧は、新ではカテゴリ木の画面。`docs/decisions/admin-layout.md` の決まったこと 3)
- 無い ID のノードを開いたとき: 旧は読み込みの失敗をコンソールに書くだけで、空のフォームが出た → 新は 404 の画面を出す(判断表の JC-04 による。銘柄・用語の編集と同じ)
- 重なりの知らせの出し方: 旧は欄の下に「[Warn]同じ名前が存在しています」を出し、欄も赤い誤りの見た目にした → 新は欄の下に「同じ名前が存在しています」(API の文。#673)を出し、欄は誤りの印にしない(決まったこと 7。銘柄のフォームと同じ。入れたそばの知らせを、保存の 422 の誤りと見分けられるようにするため)
- 英名の重なりの問い合わせ: 旧は半角にする前の入れた値で問い合わせた(全角で入れると、半角で保存する値がほかのノードと重なっても出なかった) → 新は半角にした値で問い合わせる(決まったこと 7。銘柄のフォームと同じ。保存する値で比べるため)
- 空にしたときの重なりの知らせ: 旧は問い合わせず、前に出ていた知らせを残した → 新は問い合わせず、知らせを消す(決まったこと 7。銘柄のフォームと同じ。空の欄は重ならないため)
- 続けて問い合わせたとき: 旧は後から返った応答で知らせを上書きした(先の値の結果が残ることがあった) → 新は最後に問い合わせた値の結果だけを出す(決まったこと 7。銘柄のフォームと同じ)
- 新規で親を選んでいないときの重なり: 旧のカテゴリは種別を選んでいなくても表の全体で比べ、ミドルはカテゴリを選んでいなくても親を空で問い合わせた → 新は問い合わせない(決まったこと 7。比べる親の子が決まらないため。名前の重なりは、親を選んでから欄を離れ直すか、保存の 422 で分かる)
- 親を選び直したときの重なりの知らせ: 旧は問い合わせ直さず、前の親で出した知らせを残した → 新は前の親で出した知らせを消し、欄を離れ直すと新しい親で問い合わせる(決まったこと 7。今の親の下で重ならない知らせを残さないため)

保存に失敗したときの出し方・開始位置の「時」に 0 を入れられること・同じ親の下の同じ名前を 422 にすることは `docs/decisions/admin-screens.md` の「旧との差分」、保存の API の差分は #121 の本文の「旧との差分」にある。
