# 名前の横断検索の API

#172 で決めたこと。公開の `GET /api/search?q=…`(名前から、カクテル・ノード・銘柄を種類ごとに探す)の決まり。旧は `POST /api/fromName`(`SearchController@fromName`)。

## 決まったこと

1. **一致は旧と同じ**。入力全体が英数字だけ(旧の `ctype_alnum`。空白や全角の英数字を含めば英数字だけではない)なら `name_eng` と `name_search`、それ以外は `name_search` を部分一致で探す。入力は半角・全角の空白で語に分け、それぞれを `name_search` の形(`NameNormalizer`。#171)にそろえてから探す。語のどれかに当たれば一致(OR)。英名の大文字と小文字は区別しない(DB の照合順序)
2. **入力の検証は旧の `SearchFromWord` と同じ**。必須・255 文字まで。空・空白だけ(前後の空白は半角・全角とも、フレームワークのミドルウェアが除く)は 422。旧は記号を禁じる `not_regex` も書いていたが、PHP の文字列のエスケープで、正規表現の文字クラスが `\\` の後の `]` で閉じ、続く `^` が「先頭」の印になるので、どの入力にも当たらず記号も通していた(旧の規則を PHP で動かして確かめた)。そのため記号は禁じない。語の `%`・`_` は、ふつうの文字として探す(LIKE でエスケープする。#435 でオーナーが決めた)。区切りの文字だけの入力(`・` など)は、語が無くなるので 422
3. **ノードは、旧のカテゴリとミドルを 1 つの種類 `nodes` で返す**。根(旧の種別)は返さない(旧は種別を探していなかった)。2 段目より深いノードも返す
4. **下書きのカクテルは返さない**(`docs/decisions/cocktail-detail.md` の決まったこと 1「下書きは公開の API に出さない」を、この API にも当てはめる)
5. **種類ごとに ID の順で、全件を返す**(ページに分けない。旧と同じ)。旧は並び順を指定していなかった
6. 材料名からカクテルを探す旧の「インテリジェンスサーチ」(`CocktailFactory::intelligenceSearch`)は #173 で `ingredient_matches` としてこの API に足した(下の「材料名からカクテルを探す(#173)」)。別名(読み替え)は #82 で扱う

## 材料名からカクテルを探す(#173)

#173 で決めたこと。`GET /api/search` の `ingredient_matches` の決まり。

1. **語の探し方は旧と同じ**。語は上の決まったこと 1 と同じく分けてそろえる。語ごとに、名前が語そのものか、語に `リキュール` を付けたもの(入力全体が英数字だけなら、英名で、語に空白なしで `liqueur` を付けたもの)と完全一致するノード・銘柄を探す。英数字だけの入力は英名だけ、それ以外は検索用の名前だけを見る(名前の欄と違い、英数字だけの入力で検索用の名前は見ない。旧と同じ)
2. **ノードで当たったら、そのノードと一致する材料**(`IngredientMatch`。配下(自分を含む)と、根を除く祖先。`docs/search.md` の「新しい木での意味」。#161・#162)を持つカクテル。**銘柄で当たったら、その銘柄を指定した材料**を持つカクテル。1 つの語でいくつも当たったら、どれかを使えばよい(OR)。任意の材料も対象にする(旧と同じ)
3. **語の間は AND**。どれかの語でノードにも銘柄にも当たらなければ 0 件(旧と同じ)
4. 根(旧の種別)の名前は探さない(旧も種別を探していなかった)。下書きのカクテルは返さない(旧と同じ)。ID の順で全件を返し、項目は `cocktails` と同じ `CocktailSummaryResource`

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/name-search.md)` としてここを指す。

- 英名に当たった下書きのカクテル: 旧は、英数字だけの入力で英名に当たった下書きのカクテルも返していた(`Search::find_Jap_or_Eng` が英名の条件を `orWhere` で外側に付け、下書きを除く条件がそちらに掛からない) → 新は返さない(決まったこと 4)
- `%`・`_` の入力: 旧は LIKE にエスケープせずに入れていたので、すべてに当たった → 新はふつうの文字として、名前に含むものだけに当たる(意図: #435 のオーナーの判断)
- 語が無くなる入力(`・` だけなど): 旧は名前で絞らず全件を返した → 新は 422
- 材料名からの検索(#173)で、ミドルにあたるノード(2 段目より深いノード)の名前に当たったとき: 旧は、そのミドルを指定した材料だけに一致した → 新は、そのノードの祖先(根を除く。旧ならカテゴリだけを指定した材料)と配下を指定した材料にも一致する(決まったこと 2 は #173 の本文の「ノードと一致する材料(`IngredientMatch`、#162)」による)

応答の形は、新しい画面に合わせて変えた。表示する中身は変えていない。

- 種類: 旧の `Intelligence`・`Cocktail`・`Category`・`Middle`・`Brand` → `ingredient_matches`・`cocktails`・`nodes`・`brands`。旧の `count`(合計の件数)は返さない(画面が数える)
- カクテルの項目: 一覧の表と同じ `CocktailSummaryResource`(`GET /api/cocktails/{id}/same-name` と同じ形)
- ノードの項目: 旧はミドルにだけ親のカテゴリを付けていた → 新はすべてのノードに `parent`(すぐ上の親)を付ける
- 銘柄の項目: 旧は所属のカテゴリとミドルを別の項目で返していた → 新は所属のノード 1 つ(`category`)
