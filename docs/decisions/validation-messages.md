# 検証のメッセージの言語

#651 で決めたこと。API の 422(`errors` と `message`)のメッセージを日本語にする。管理 API の欄の名前(`:attribute`)は #692 で決めた(下の 4)。

## 決まったこと

1. **`lang/ja` を置き、ロケールを `ja` にする**(FormRequest ごとに `messages()` を書く案は採らない)
   - サーバーの `.env` は前から `APP_LOCALE=ja`(`deploy-env.yml`)で、`lang/ja` が無いため `APP_FALLBACK_LOCALE`(`en`)の英語が出ていた。`backend/lang/ja/validation.php` を置けば、サーバーの設定を変えずに日本語になる
   - 手元と CI の `.env` の元(`backend/.env.example`)も `APP_LOCALE=ja` にし、`config/app.php` の既定も `ja` にする。テストもサーバーと同じ日本語のメッセージで動く
   - FormRequest ごとに書く案は、規則を足すたびに書き足す手間があり、書き忘れると英語に戻る。全体を日本語にしても困るところが無い(下の 3)ので採らない
2. **メッセージの形**
   - `backend/lang/ja/validation.php` は、Laravel の `lang/en/validation.php` と同じキーをすべて持つ(テストで確かめる。Laravel を上げて規則が増えたら足す)
   - 欄の名前(`:attribute`)は、英語のキーのまま出す(`per pageは50以下にしてください。`。キーの `_` は Laravel が空白にして出す)。ただし管理画面の入力の欄は、#692 で日本語にした(下の 4)
   - `message`(1 つめのメッセージ)に付く「ほかの誤りの数」は `backend/lang/ja.json` で `(ほか N 件)` にする
   - 規則のクロージャで出す独自のメッセージも、同じ言語の行を使う(条件検索の ID に真偽値・小数を送ったときの `validation.integer`)。もとから日本語で書いたメッセージ(`NotRootCategory`・記法の誤りなど)は変えない
3. **公開の API も日本語になる**。ロケールは管理と公開で分けない
   - 変わるのは 422 のメッセージの文字だけで、`errors` のキー・状態コード・本文の形は変わらない(`openapi/openapi.json` も変わらない)
   - FE はメッセージの文字で分岐していない。管理画面(設定・銘柄・用語辞典など)はメッセージを画面にそのまま出す。公開の画面は 422 のメッセージを出さない
4. **管理画面の入力の欄の名前は、日本語(画面の欄の名前)で出す**(#692)
   - 設定の画面のように、複数の欄の誤りをまとめて出すところでは、キーのまま(`valueの形が正しくありません。`)だと、どの欄の誤りか読みにくいため
   - 名前は、管理の FormRequest(`app/Http/Requests/Admin/`)ごとに `attributes()` に書く。`lang/ja/validation.php` の `attributes` には書かない。`name` が、銘柄では「名前」、言い換えでは「変換前」、スキップ語では「スキップ語」のように、画面によって違う欄を指すため。全体に書くと、公開の API の欄の名前も変わる
   - 名前は、画面の欄の見出し(`frontend/src/features/admin-*` の `label`)に合わせる。言い換えの `command`・`note` は、画面の見出しも英語なのでそのまま
   - YouTube・画像の欄は、銘柄・カクテル・用語・ノードで共通なので、`AdminFormInput` の `youtubeAttributes()`・`imageAttributes()` にまとめる。ノードの編集でその場で作る銘柄の欄(`brand_*`)は「有名な銘柄の」を前に付ける
   - カクテルの材料の行・別名は、何行目・何番目かを付ける(`材料 2 行目の量を入力してください。`・`別名 1 つ目は255 文字以下にしてください。`。Laravel の `:position` で 1 から数える)
   - 設定の `value` は、その項目の見出し(`SettingDefinitions` の `label`。`Amazon のパートナータグの形が正しくありません。`)にする。定義に無いキーのときは「値」。`key` は「項目」
   - 変えないもの: 公開の API の欄の名前と、管理の一覧・重複の確かめなど、画面の入力の欄でないクエリ(`q`・`page`・`per_page`・`exclude_id` など。コントローラの中の `validate()`)は、英語のキーのまま
5. 変えないもの: 検証でないエラーの `message`(`Unauthenticated.`・`CSRF token mismatch.` など)は、言語の行を通らないので英語のまま

## 旧との差分(意図: #692)

旧システムの 422 のメッセージは、旧システムを動かして確かめていない(#651 の PR のテストの表では `未確認`)。ここでの「旧」は、#651 までの新システムの出し方(欄の名前が英語のキーのまま)を指す。

- 設定の `value`: 旧は `valueの形が正しくありません。` → 新は項目の見出し(`Amazon のパートナータグの形が正しくありません。`)。定義に無いキーは `値`、`key` は `項目`
- 言い換えの `name`: 旧は `nameを入力してください。` → 新は `変換前を入力してください。`(スキップ語は `スキップ語`、銘柄は `名前`)
- 銘柄・カクテル・用語・ノードの欄(`parent_id` など): 旧は英語のキー → 新は画面の欄の見出し(`所属`・`度数`・`開始位置(分)`・`リンク URL` など)
- カクテルの材料の行・別名: 旧は英語のキー(`ingredients.1.amount` など) → 新は `材料 2 行目の量`・`別名 1 つ目`
- ノードでその場で作る銘柄の欄(`brand_*`): 旧は英語のキー → 新は `有名な銘柄の` を前に付けた名前
- 変えない: 公開の API の欄の名前と、管理の一覧・重複の確かめのクエリ(英語のキーのまま)
