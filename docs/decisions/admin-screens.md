# 管理画面で、旧と同じにできない・issue が旧と違うところの扱い

#284 で決めたこと。決めた経緯と案ごとの比較は #284 の本文とコメントにある。

管理画面の issue(#65・#119〜#129・#289〜#292・#308・#314 など)を、旧の画面(`laravel6/resources/js/Admin/*`)と BE(`laravel13` の `DetailEditController`・`Requests/Detail/Edit/*`)と突き合わせると、旧に無い機能や旧と違う動きを前提にしている issue があった。そのうち 8 つをオーナーが決めた([#284 のコメント](https://github.com/t-moriyama-r/cocktail-db/issues/284#issuecomment-6417347518)の「全部おすすめで」。2026-10-26)。1 は B、2〜8 は A。

## 決まったこと

1. **下書きと公開は、保存のボタンで決める**。「下書きとして保存」「公開する」の 2 つのボタンにする。説明を書いた途中のものも下書きにできる。旧は保存のボタンが「送信」1 つで、説明が空なら下書き、入っていれば公開になった(公開済みのカクテルの説明を消して保存すると下書きに戻った)
2. **名前の重複は、ノードだけ保存を止める**。カテゴリ木のノードは、同じ親の下に同じ名前のノードがあれば 422 にする。カクテルは旧と同じく警告だけで、保存できる
3. **カクテルの重複チェックは、旧の名前での一覧に、同じレシピの警告を足す**。旧と同じく、名前・英名が同じカクテルを集めて材料の近い順に並べて出し(保存は止めない)、それに加えて、材料の組が同じカクテル(#82 の `recipe_signature` が同じもの)があれば警告する。「その他」だけで作ったカクテルの警告は作らない
4. **材料の量は、旧と同じく整えるだけで検証しない**(`30` → `30ml`、`-` → `適量` など。旧 `RecipeCalc::format_amount` と同じ整え方)。量の正規表現(旧 `App\Rules\Amount`)に合わない既存の量も、開いてそのまま保存できる
5. **材料の行は、追加・削除・並べ替えができる**。最低 2 件(旧と同じ)、上限 20 件
6. **管理画面の一覧は、名前・英名の部分一致で絞り、50 件ずつのページングにする**
7. **ログインの後は、開こうとしていた URL に戻す**(#119 の受け入れ条件のとおり)
8. **YouTube の開始位置の「時」に 0 を入れられる**(開始位置は秒にして保存する)

### 既定(問いにしなかったもの)

- **保存に失敗したら、項目ごとにメッセージを出し、画面を移らない**。入力は残す
- **カクテルの削除は、確かめてから消す**

### 決まったことに書かれていないこと

#284 の問いの外で、後の issue で決めることになるもの。ここでは決めない。

- **既にある、同じ親の下の同じ名前のノード**: 旧 DB には、同じ親(根)の下で同じ名前のカテゴリが 1 組ある(下の「旧 DB で確かめた事実」)。`docs/migration-anomalies.md` の 6 でそのまま移すと決めているので、決まったこと 2 のまま作ると、移した後はどちらかの名前を変えるまで、どちらを保存しても 422 になる。名前を変えさせるか、名前を変えない保存は通すかは、ノードの API(#121)で決める
- **銘柄・用語辞典の名前の重複**: 決まったこと 2 が名前を挙げたのはノードとカクテルだけ。銘柄の API(#314。実装済み)は「ノード以外は警告」と読んで、警告だけにした。旧 DB にも、同じ所属で同じ名前の銘柄が 4 組ある
- **説明が空のカクテルを「公開する」で保存できるか**: 決まったこと 1 は、説明の有無と公開を切り離したが、公開に説明を必須にするかは決めていない。旧は説明の無い公開のカクテルを作れなかった(旧 DB でも 0 件)。カクテルの API(#291)で、旧に合わせて、説明が空のまま「公開する」で保存すると 422 にした(下書きは説明が空でも保存できる。#291 の「旧との差分」)
- **同じレシピの警告をどの画面に出すか**: 決まったこと 3 の警告を、編集画面のどこに出すか(名前での一覧と並べるか、別に出すか)は、カクテルの編集画面(#127)と重複チェック(#129)で決める

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-screens.md)` としてここを指す。#284 の本文の既定には `差分あり(意図: 失敗に気づけるようにする)` と書くようにあったが、節を持つ文書を指す決まり(CLAUDE.md の「旧との差分」)に合わせて、既定の 2 つもこの文書を指す。

- 下書きと公開: 旧は保存のときに説明が空なら下書き、入っていれば公開(公開済みの説明を消して保存すると下書きに戻る) → 新は「下書きとして保存」「公開する」のどちらのボタンで保存したかで決める(決まったこと 1)
- 同じ親の下の同じ名前のノード: 旧は「[Warn]同じ名前が存在しています」と出すだけで保存できた → 新は 422 で保存を止める(決まったこと 2)
- 材料の組が同じカクテル: 旧は名前が同じカクテルの中で並べ替えるだけで、名前の違う同じレシピのカクテルは出なかった → 新は `recipe_signature` が同じカクテルがあれば警告する(決まったこと 3)
- 材料の行: 旧は 12 行の枠で(材料が 12 件を超えるカクテルは無かった)、行の追加・削除・並べ替えは無かった → 新は行を足す・消す・並べ替えるができ、上限は 20 件(決まったこと 5)
- 一覧の絞り込み: 旧は名前・英名の前方一致(「ム」では「ラム」は出ない) → 新は部分一致(決まったこと 6)
- 一覧のページング: 旧は全件を 1 枚に出した → 新は 50 件ずつ(決まったこと 6)
- ログインの後の行き先: 旧は必ず管理画面のメニュー(`/admin`)に戻った → 新は開こうとしていた URL に戻す(決まったこと 7)
- 開始位置の「時」: 旧は 1 以上でないと 422 で、0 は入れられなかった → 新は 0 を入れられる(決まったこと 8)
- 保存に失敗したとき: 旧は画面ごとに違い、カクテルは結果を待たずに一覧へ移って失敗が出ず、カテゴリ・ミドルは失敗をコンソールに書くだけでメニューへ移り、銘柄はサーバーのメッセージを alert で出して画面に残った → 新はどの画面も項目ごとにメッセージを出し、画面を移らない(既定)
- カクテルの削除: 旧は「削除」を押すと確かめずに消した(結果も待たずにメニューへ移った) → 新は確かめてから消す(既定)

旧と同じにするもの(差分ではない): 4(量を整えるだけで検証しない)、2 のうちカクテルの名前の重複(警告だけ)、3 のうち名前で集めて材料の近い順に並べる一覧。

## 理由

- 1: AI の取り込み(#84)は説明つきの下書きを作るので、説明の有無で下書きを決めると、取り込んだものがすぐ公開になってしまう。説明を書いている途中のものを下書きのまま置いておけるようにもする
- 2: 同じ親の下で同じ名前のノードは、木の画面で見分けられない。カクテルは、同じ名前で別のレシピのものが実際にある(旧 DB で名前の重なりが 703 組)ので止めない
- 3: 同じレシピの警告は、取り込み(#84)の「同じ材料構成なら登録しない」と判定がそろう。「その他」だけの警告は、何を防ぎたいのかが決まっていない
- 4: 正規表現で止めると、合わない既存のカクテルは量を直さないと保存できなくなる。旧の管理画面でも検証していなかった
- 5: 行の上限は、旧のデータの最大(11 件)に余裕を持たせた
- 6: 管理者が名前の一部しか覚えていないときに探せるようにする。カクテルは約 5,700 件あり、全件を 1 枚に出すのは重い
- 7・8: 開始位置は秒にして保存するので、0 時間は自然な入力。ログインの後に開こうとしていた画面へ戻るのは #119 の受け入れ条件
- 既定: 旧は保存や削除に失敗しても気づけなかった(旧の不具合)

## 旧ソースで確かめた事実

本番の BE(`laravel13/`)と、画面の Vue のソース(`laravel6/resources/js/`)を読んだ。画面については、本番の画面のビルド(`production-public/`)でも、保存・削除・材料の 12 行・一覧の前方一致が同じであることを確かめた。旧システムを動かして確かめてはいない。

| どこ | 何をしているか |
|---|---|
| `laravel13/app/Classes/Factory/FactoryHelper.php` の `generateFromRequest` | カクテルの保存で `is_draft = empty(description)`。保存のたびに説明の有無で下書きかどうかを決め直す |
| `laravel6/.../Admin/Super/Detail/CocktailEdit.vue` | 保存のボタンは「送信」1 つ。`send` は `axios.post` を `await` せずに呼び、結果を待たずに一覧へ移る(`try`・`catch` は効かず、失敗は画面に出ない)。`deleteExe` は確かめずに削除の API を呼び、結果を待たずにメニューへ移る |
| `laravel6/.../Detail/CategoryEdit.vue`・`MiddleEdit.vue` | 保存は `await` するが、失敗は `console.log` だけで、メニューへ移る |
| `laravel6/.../Detail/BrandEdit.vue` | 保存に失敗したら、サーバーのメッセージを `alert` で出し、画面に残る |
| `laravel6/.../Detail/component/NamesAndDescription.vue` | 名前・英名を変えると `duplicate_check` に問い合わせ、重なれば欄の下に「[Warn]同じ名前が存在しています」を出す。保存は止めない |
| `laravel13/app/Http/Controllers/Auth/DetailEditController.php` の `duplicate_check` | 名前の重なりの範囲は種類で違う。ミドルは同じ親の下だけ、カテゴリ・銘柄・カクテル・用語辞典は表の全体で比べる(銘柄は画面が親を送るが、BE は使わない) |
| 同 `duplicate_get` | 英名が同じか、正規化した名前が同じカクテル(自分を除く。下書きも含む)を集め、「材料のカテゴリの組と量まで同じ」「カテゴリの組が同じ」「自分の材料をすべて含むが数が違う」「それ以外」の 4 つの順に並べて返す。材料の構成だけで探す処理は無い |
| 同 `is_kind5_check`・`is_kind5_check_kindver` | 種別が 4・5(新の根の役割 `soft_drink`・`other`)かどうかを返すだけ。`is_kind5_check` を呼ぶのはミドル、`is_kind5_check_kindver` を呼ぶのはカテゴリ・用語辞典の編集画面で、有名な銘柄の検証を省くかを決めるため(用語辞典では何にも効いていない。#315)。カクテルの保存では使わない |
| `laravel13/app/Classes/Factory/RecipeCalc.php` の `format_amount` | 数字だけなら `ml` を付ける(「その他」の材料で `1` なら `1個`)。`-` は `適量`、`t`・`m`・`da`・`dr`・`c` の省略は `tsp`・`ml`・`dash`・`drop`・`cup` に直す。検証はしない |
| `laravel13/app/Rules/Amount.php` | 量の正規表現。使うのは自動取り込み(`RecipeInstance`・`AutoInputTrait`・`AutoInputInfo`)だけで、管理画面の保存(`EditCocktailValidate`)では使わない |
| `laravel13/app/Http/Requests/Detail/Edit/EditCocktailValidate.php` | 材料は 1・2 行目のカテゴリが必須(2 件以上)。量はカテゴリがあれば必須(書式は見ない)。開始位置は `youtube_time_hour` が `min:1`、分・秒は `max:59` だけ(下限は BE に無く、0〜59 にしていたのは画面の数字の欄) |
| `laravel6/.../Detail/component/RecipeList.vue` | 材料の行は、今の材料に空の行を足して 12 行にする(材料が 12 件を超えれば、その数だけ出す)。行の追加・削除・並べ替えの操作は無い |
| `laravel6/.../Admin/Super/ListComponent.vue` | 一覧は全件を出し、絞り込みは名前・英名の前方一致(片仮名を平仮名にそろえ、英名は小文字にそろえる) |
| `laravel6/resources/js/routes.js`・`laravel13/.../Auth/TwitterController.php` | 未ログインで管理画面を開くと、元の URL を持たずにログインの画面へ移る。ログインの後は必ず `admin` の名前のルート(`/admin`)へ移る |
