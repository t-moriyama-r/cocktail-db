# 管理画面の用語辞典の編集

#66 で決めたこと。決めたのは #66 の本文の「追記: 旧の画面で確かめた仕様」(オーナーが書いた)で、ここはそれを、テストの表から指せる「旧との差分」の節にまとめたもの。相手の API(検証・削除の規則)は #315。

## 決まったこと

1. 一覧(`/admin/dictionaries`)は、分類ごとに見出し「〈分類の名前〉(〈英名〉)」と、その用語「〈名前〉(〈英名〉)」を並べる。分類は ID の順、用語はかな・全角をそろえた名前の順(並べるのは API。#315)。用語が 0 件の分類は出さない(旧と同じ)
2. 一覧の用語のリンクは、用語の編集の画面(`/admin/dictionaries/{id}`)を開く。一覧の上に新規の画面(`/admin/dictionaries/new`)へのリンクを置く
3. 新規・編集の欄は、分類(選択。用語の無い分類も選べる)・名前・英名・説明・YouTube と開始位置(時・分・秒)・画像・リンクテキスト・リンク URL(`docs/schema.md` の `dictionaries`)。旧の編集画面はカテゴリの編集画面を写したまま途中でやめたもので、写す項目は無い
4. 保存に失敗したら、欄ごとに誤りを出し、画面を移らない。入力は残す(`docs/decisions/admin-screens.md` の既定)。保存できたら一覧へ移り、保存したことを出す
5. 削除は確かめてから消す。消せないとき(カクテルのグラスに使われている・技法を説明する用語になっている。#315)は、API が返す理由をそのまま出し、画面に残る。消せたら一覧へ移り、消したことを出す
6. 旧 `DictionaryEdit.vue` の「その他」かどうかで検証を変える分岐(`is_kind5`)は移さない(旧で何にも効いていなかった。#315 の 4)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-dictionary.md)` としてここを指す。旧の挙動は旧ソース(`laravel6/resources/js/Admin/Super/DictionaryList.vue`・`Detail/DictionaryEdit.vue`、`routes/web.php`)から読み取ったもので、旧を動かして確かめてはいない。

- 一覧の用語のリンク先: 旧はカクテルの編集画面(`AdminCocktailEdit`)を、用語の ID で開いていた(旧の不具合) → 新は用語の編集の画面を開く
- 用語の保存: 旧は保存の API を止めていて(「面倒なのでサポート切り」)、新規・編集・削除ができなかった → 新はできる(保存の失敗・削除の確かめは、ほかの管理画面と同じ。`docs/decisions/admin-screens.md`)
