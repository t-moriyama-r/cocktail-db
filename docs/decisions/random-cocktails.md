# ランダムなカクテルの一覧の部品

#300 で決めたこと。カテゴリ・銘柄・カクテル・用語の詳細で使う「これを使ったカクテル(ランダム5種)」と「再取得」の一覧(旧 `Detail/component/RandomCocktail.vue`)を、1 つの部品(`frontend/src/components/RandomCocktails/`)にした。呼ぶ API と、何が当たるかは `docs/decisions/related-cocktails.md`。

## 決まったこと

1. **見出しは旧と同じ**。カクテルが起点なら「材料が似たカクテル」、ベースが起点なら「同じベースのカクテル」、ほか(ノード・銘柄・技法・グラス)は「これを使ったカクテル(ランダム〈件数〉種)」。件数の既定は 5(旧の用語の技法・グラスは 7 を渡していた)
2. **0 件でも見出しを出す**(旧と同じ。`docs/decisions/public-detail.md` の既定)。表は列の見出しの行だけになる(旧と同じ)。読み込み中は見出しと「再取得」だけを出す(旧と同じ)
3. **「再取得」を押すと同じ起点で取り直し、新しい一覧が届くまでは今の一覧を出したままにする**(旧と同じ)
4. **起点が変わったら、今の一覧を消して取り直す**(旧と同じ)。旧の用語詳細は技法が変わっても取り直さなかったが、それは写さない(#300 のやること 3)
5. **API が失敗したら、見出しの下にエラーの表示と「もう一度読み込む」を出す**(#98 の決まりと同じ)
6. **起点のカクテルが下書き・無い ID(API が 404)なら、当たるものが無いのと同じく 0 件の表にする**。この部品は詳細の画面の一部で、詳細そのものの 404 は詳細の画面が出す

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/random-cocktails.md)` としてここを指す。旧での結果は、旧ソース(本番の `production-public/` のビルドと `laravel6/resources/js/`)から読んだもの。旧システムを手元で動かして確かめてはいない。

- 技法が起点で、技法が変わったとき: 旧は取り直す条件に技法が入っておらず(`propSet` に `methodid` が無い)、前の一覧が残った → 新は起点が変わったら種類を問わず取り直す(決まったこと 4)
- 起点が変わった後に、前の起点の応答が遅れて届いたとき: 旧は届いた順に一覧を上書きし、前の起点の一覧が出ることがあった → 新は今の起点の応答だけを出す(決まったこと 4)
- 起点のカクテルが下書き: 旧は下書きでも材料が似たカクテルを出した → 新は 0 件の表(決まったこと 6。API が 404 を返すのは `docs/decisions/related-cocktails.md`)
- 起点のカクテルが無い ID: 旧は API がエラー(500)になり、alert を出してページを読み直した → 新は 0 件の表(決まったこと 6)
- 「再取得」: 旧はクリックだけを受ける文字(`span`)で、キーボードでは押せなかった → 新はボタンにし、キーボードでも押せる。見た目(リンクの色・指すと下線)は旧と同じ
