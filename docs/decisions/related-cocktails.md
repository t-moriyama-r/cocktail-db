# 別のカクテルの API

#174 で決めたこと。詳細ページの「別のカクテル」(旧の「ランダムカクテル」。旧 `POST /api/getRandomCocktail` → `DetailController@regetCocktails` → `CocktailFactory::RandomByGetRandom`)を返す、公開の `GET /api/cocktails/{id}/related`(カクテルを起点にする)と `GET /api/cocktails/random`(ノード・銘柄・ベース・技法・グラスを起点にする)の決まり。

旧の画面(`component/RandomCocktail.vue`)は、カクテルの詳細で「材料が似たカクテル」(カクテル)と「同じベースのカクテル」(ベース)、カテゴリ・ミドル・銘柄の詳細で「これを使ったカクテル」、用語辞典の技法・グラスの項目で同じく「これを使ったカクテル」を出していた。件数は 5 件(技法・グラスは 7 件)で、「再取得」を押すと選び直す。

## 決まったこと

1. **どの起点でも、下書きは出さず、当たるカクテルからランダムの順で `limit` 件まで返す**(#174 の「やること」)。`limit` は旧と同じく必須で、1〜50(#174 の受け入れ条件)。1 件ごとの形は、同じ名前の API と同じ一覧の表の行(`CocktailSummaryResource`)
2. **起点はちょうど 1 つ**。`GET /api/cocktails/random` は `category_id`(ノード)・`brand_id`(銘柄)・`base_id`(ベース)・`method_id`(技法)・`glass_id`(グラス)のどれか 1 つを受ける。カクテルを起点にするときは `GET /api/cocktails/{id}/related`
3. **ノードを起点にするとき**: そのノードか、その配下か、より大まかなノード(祖先。根を除く)を材料に使うカクテル。`IngredientMatch::matchingNodeIds`(`docs/search.md` の「新しい木での意味」。#161)と同じ一致。旧 `getCocktailIds` はカテゴリを起点にするとミドルを問わずそのカテゴリの材料(配下)を、ミドルを起点にするとそのミドルとカテゴリだけを指定した材料(祖先)を当てていた
4. **銘柄を起点にするとき**: 銘柄の所属するノードか、その祖先(根を除く)の材料で、銘柄がその銘柄か、銘柄を指定していないもの。配下のノードの材料は当てない(旧 `getCocktailIds` は銘柄を指定すると、銘柄のミドルか、ミドルを指定していない材料に絞っていた。ミドルの無い銘柄では、ミドルを指定していない材料だけ)。同じノードでも別の銘柄を指定した材料は当てない
5. **ベース・技法・グラスを起点にするとき**: ベース(`base_category_id`)・技法・グラスがその ID と同じカクテル。木はたどらない(旧も列が同じものだけ)
6. **カクテルを起点にするとき**: 材料を並び順(`position`)で見て、最初の 2 つの材料のどちらかに一致する材料を使うカクテル(和集合。旧 `RandomByIDs2onlyId`)から選ぶ。それで `limit` 件に足りなければ、3 つめから材料を 1 つずつ順に足し、`limit` 件以上になったところで止める(#174 の「やること」)。材料ごとの一致は、銘柄つきの材料は 4.、銘柄の無い材料は 3. と同じ(旧も材料のカテゴリ・ミドル・銘柄を `getCocktailIds` に渡していた)。任意の材料も数える(旧も `is_optional` を見ていない)。**起点のカクテル自身は返さず、件数にも数えない**(#440 で決めた。旧は自分も返していた)
7. **起点のカクテルが下書き・無い ID なら 404**(`docs/decisions/cocktail-detail.md` の決まったこと 1 と同じく、下書きは公開の API に出さない)。無いノード・銘柄・ベース・グラスを起点にしたら 0 件(旧と同じ)。無い技法は 422(旧も 1〜6 だけを受けていた)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/related-cocktails.md)` としてここを指す。旧での結果は、旧ソース(本番の `laravel13/`)の `CocktailFactory`・`RegetCocktailValidate` から読んだもの。旧システムを手元で動かして確かめてはいない(#174 の PR で「未確認」にしている)。

- `limit` の上限: 旧は上限が無く、送った数まで返した → 新は 51 以上を 422(決まったこと 1)
- `limit`・起点の ID の小数: 旧は数(`numeric`)なら小数も通した → 新は整数だけを受け、小数は 422
- カクテルを起点にして、最初の 2 つの材料で `limit` 件に足りないとき: 旧は材料を足す処理の呼び出しの引数が足りず(`RandomByIDsonlyId` に 4 つ要るところへ 3 つ)、エラー(500)になる → 新は材料を順に足す(決まったこと 6)
- 材料が 1 つ以下のカクテルを起点にしたとき: 旧は 2 つめの材料が無くエラー(500)になる → 新はある材料だけで探す(材料が無ければ 0 件)
- 起点のカクテルが下書き: 旧は下書きでも探した → 新は 404(決まったこと 7)
- 起点のカクテルが無い ID: 旧はエラー(500) → 新は 404(決まったこと 7)
- 起点のカクテル自身: 旧は自分の材料が必ず一致するので、材料が似たカクテルに自分も出た → 新は自分を除く(決まったこと 6。#440)
- 起点を 2 つ以上送ったとき: 旧は base・category・cocktail・method・glass の順で先のものだけを使った(旧の画面は 1 つしか送らない) → 新は 422(決まったこと 2)
- 起点の名前と形: 旧は `POST` の本文で `category`・`middle`・`brand`・`cocktail`・`base`・`method`・`glass` を受け、ミドル・銘柄を起点にするときも親のカテゴリを一緒に送っていた → 新は `GET` で、ノード(カテゴリもミドルもノード)・銘柄の ID だけを送る。どのカクテルが当たるかは変えていない(決まったこと 3・4)
