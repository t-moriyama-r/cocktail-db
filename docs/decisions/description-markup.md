# 管理画面の説明文の自動リンク(保存のときの変換と、編集で開くときの注釈)

#287 で決めたこと。記法そのもの(`@n`・`@c`・`@b`・`@d`)は #285 で決める。変換は `App\Services\DescriptionMarkup` が受け持ち、ノード・カクテル・銘柄・用語の管理 API(#121・#291・#64・#66)は、説明文(`description`)とカクテルの `note` の保存と取得でこれを通す。

## 決まったこと

1. **保存のとき**(`DescriptionMarkup::toStored`。旧の `Markup::mark_up`)。次の順に変換する
   1. 編集で開くときに添えた名前(`{!…!}`)を取り除く
   2. 名前で書いた記法(`@c名前@` など)を ID の記法(`@c<ID>@`)に直す。種類は `n`(ノード)・`c`(カクテル)・`b`(銘柄)・`d`(用語)。大文字で書いた記法は大文字のまま残す(旧と同じ)。ID で書いた記法はそのまま残す
   3. 旧で決め打ちしていた漢字の名前(旧の `MIDDLE_PREG`・`CATEGORY_PREG`。「芋焼酎」「砂糖」など)を、名前の一致するノードの記法にする。旧と同じくミドルの組を先に置き換える。一致するノードが無ければ、名前をそのまま残す
   4. 片仮名の並び(2 文字以上。先頭は長音・中黒でない)を、名前が一致するノード → カクテル → 銘柄 → 用語の順に探し、`@n<ID>@`・`@c<ID>@`・`@b<ID>@`・`@d<ID>@` に置き換える。一致が無ければそのまま
2. 名前は `name_search` の形(`NameNormalizer`)にそろえて比べる
3. 3・4 で探すノードに、根(旧の種別)は入れない(旧は種別を探さなかった)。2 の名前で書いた記法(`@n蒸留酒@`)は、書いた人が指したものなので根も指せる
4. 同じ名前のノードが複数あるときは、浅いもの(祖先の少ないもの)、同じ深さなら ID の小さいものを選ぶ
5. 次のときは 422 にする(エラーは入力の名前に付ける)
   - 名前で書いた記法の名前が見つからない
   - 記法の種類が `n`・`c`・`b`・`d` のどれでもない。旧の `p`・`m` も含み、名前で書いても ID で書いても(`@pラム@`・`@m12@`)止める
   - 文末に閉じていない記法がある(`@` と英字の後が数字のときだけ。旧と同じく、メールアドレスのような書き方は通す)
   - UTF-8 でない文字列
6. **編集で開くとき**(`DescriptionMarkup::withNotes`。旧の `Markup::at_id_append_note`)。ID の記法の後に、指す先の名前を `{!名前!}` で添える(例: `@n12@{!ラム!}`)。2 段より深いノードは、旧のミドルと同じく「親の名前/名前」にする。指す先の無い記法は、旧と同じく取り除く。空の文字列は、旧と同じく null にする

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/description-markup.md)` としてここを指す。

- 片仮名の並びを探す順: 旧はカテゴリ → カクテル → ミドル → 銘柄 → 用語 → 新はノード(カテゴリとミドルをまとめたもの)→ カクテル → 銘柄 → 用語(#287 の「やること」1)
- 保存する記法: 旧はカテゴリを `@p<ID>@`、ミドルを `@m<ID>@` にしていた → 新はどちらも `@n<ノードの ID>@`(#285・#287)
- 名前で書いた記法の名前が見つからないとき: 旧は例外を投げていた(HTTP 500)→ 新は 422(#287 の「やること」1)
- 片仮名の並びがミドルとカクテルの両方の名前に一致するとき: 旧はカクテルを先に探したのでカクテルの記法になっていた → 新はノードの記法になる。旧のデータでは 5 件(クレーム・ド・カフェ、アイリッシュコーヒー、サワーアップル ×2、オレンジスカッシュ)。上の「探す順」の差分から出るもの(#287 の「やること」1 が新の順を決めている)
- 記法の種類が `p`・`m`・そのほかの英字のとき: 旧は、名前で書いた `@p名前@` と `@x名前@` は例外(HTTP 500)、`@m名前@` はミドルの ID に直し、ID で書いた記法(`@m12@`・`@x12@`)はそのまま保存していた → 新はどれも 422(新の記法の種類は `n`・`c`・`b`・`d` だけで、ほかの英字の記法は表示できない参照になる。ノードは `@n名前@` で書ける)
- 決め打ちの漢字の名前のノードが無いとき: 旧は ID の無い記法(`@p@`)を入れていた(旧のデータでは「巨峰」「グラニュー糖」の 2 語)→ 新は名前をそのまま残す(`@n@` は参照にならず、旧の結果を新の記法に写せない)
- 同じ名前のノードが複数あるとき: 旧はカテゴリをミドルより先に探し、同じ表の中では順を決めていなかった(DB が返した順)→ 新は浅いもの、同じ深さなら ID の小さいもの(結果を毎回同じにするため)
- UTF-8 でない文字列: 旧は正規表現が失敗し、説明文が空の文字列で保存された → 新は 422(説明文が消えるのを防ぐ)
