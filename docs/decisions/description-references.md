# 説明文の参照の記法と、移行での直し方

#285 で決めたこと。記法の一覧は [schema.md](../schema.md) の「説明文の参照の記法」。移行で直すのは `legacy:import` の `descriptions`(`App\Services\LegacyImport\DescriptionImporter`。直し方は `LegacyDescriptionReferences`。記法の壊れたところを直す前の段は `LegacyDescriptionRepairs`)、直した後に指す先があるかを確かめるのは `data:verify`。画面に出すとき(#286)は [description-segments.md](description-segments.md)、管理画面で保存するとき(#287)は [description-markup.md](description-markup.md)。

## 決まったこと

1. **記法は `@<種類><ID>@`**。種類は `n`(ノード)・`c`(カクテル)・`b`(銘柄)・`d`(用語)。カテゴリとミドルは 1 つのノードになるので、旧の `@p`(カテゴリ)・`@m`(ミドル)を `@n<ノードの ID>@` にまとめる。カクテル・銘柄・用語は ID を変えずに移すので、`@c`・`@b`・`@d` の ID はそのまま
2. **移行では、旧の値から直す**。説明文は、ほかの表の行を指す(カテゴリの説明が、後から作るミドルを指すなど)ので、ほかの部分を移した後に、最後の部分 `descriptions` で直す。直すのは旧の値からで、新しい DB の値は読まない(何度流しても同じ結果・同じ件数になる)。移した先の行が legacy_id_maps に無いとき(ほかの部分をまだ移していない)は、どの行かを添えて止め、何も書かない
3. **直す対象**は、旧の説明文の列すべて: 種別(`m_category_kinds`)・カテゴリ(`m_category`)・ミドル(`m_middle`)・技法(`m_method`)・用語(`t_dictionary`)・銘柄(`m_brand`)・カクテル(`t_cocktails`)の `description` と、カクテルの `note`
4. **`@p<ID>@`・`@m<ID>@` は、legacy_id_maps(`m_category`・`m_middle` → `categories`)で `@n<ノードの ID>@` にする**。対応の無い ID(旧で消えたカテゴリ・ミドルを指していたもの)は、記法を取り除いて前後の文字だけを残し、件数に数える(記法は ID しか持たず、残せる名前が無いため)
5. **大文字の記法(`@P`・`@M`・`@C`・`@B`・`@D`)は、小文字と同じ意味として小文字にそろえる**(旧の `generateDiscriptionArray` も大文字と小文字を同じに扱っていた)。管理画面で保存するときは大文字のまま残す(#287)が、どちらも画面では同じに出る(#286)
6. **記法の形でないものは、参照として書き換えない**。ID の無い `@p@`、0 で始まる ID(`@p0@`)、閉じていない記法(`前に@p12`)、ほかの英字(`@x12@`)、メールアドレスなど。読み方は旧と同じく、`@`・種類の英字・0 で始まらない数字・`@` の並び(DescriptionParser・DescriptionMarkup と同じ形)。ただし、記法の外に残った `@`・`＠` は、管理画面で保存できなくなる(#392)ので、この前に取り除く(#393。下の 9)
7. **出す件数**: `@p・@m を @n に直した参照`・`対応するノードが無く記法を外した参照`・`@C・@B・@D を小文字にした参照`(9 の件数は [migration-anomalies.md](../migration-anomalies.md) の 14)
8. **`data:verify` で、説明文の参照を確かめる**。次の 3 つを、どの表のどの行の列か・どの記法かを挙げて失敗にする。移行の検証(`legacy:verify`。#35)は `data:verify` を呼ぶので、そこからも確かめられる
   - 指す先が無い参照(`@n`・`@c`・`@b`・`@d`。大文字も)。画面では黙って取り除かれる(#286)ので、機械で見つける
   - 旧の記法(`@p<ID>@`・`@m<ID>@`)が残っている。`@c5@p7@` のように前の記法と `@` を 1 つ分け合う形は、新の読み方では 1 つ目の記法の後の `p7@` が記法にならず、移行で直せないので、ここで見つける
   - 記法の外に `@`・`＠` が残っている(管理画面で保存するときの検査(#392)を通らない)。列ごとに、最初に残った `@` の前後の文字を挙げる。旧の記法が残る列は、上の旧の記法だけを挙げる(#393)
9. **記法の壊れた説明文は、参照の記法を直す前に、旧の値から直す**(#393。直し方と件数は [migration-anomalies.md](../migration-anomalies.md) の 14。`LegacyDescriptionRepairs`)。手での打ち間違い(14 の A〜E)は、表・列・ID と直す前の部分を対にして直し、直す前の部分が見つからなければ直さずに行を出す。旧に無いカクテルを指す `@c<ID>@`(14 の F)は記法を取り除く。それでも記法の外に残った `@`・`＠` は取り除いて文字だけを残し、行を出す(移行は止めない)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/description-references.md)` としてここを指す。旧での結果は、旧を手元で動かせなかったので実測していない(旧の `Markup` のソースから読んだもの)。

- 保存する記法: 旧はカテゴリを `@p<カテゴリの ID>@`、ミドルを `@m<ミドルの ID>@` で持っていた → 新はどちらも `@n<ノードの ID>@`(決まったこと 1・4)
- 大文字の記法: 旧は `@P12@` などを大文字のまま持っていた → 新は移行で小文字にそろえる(決まったこと 5)。画面での出方は変わらない
- 対応するノードが無い `@p`・`@m`: 旧は画面に出すときに型のエラーで 500 になり、編集で開くと記法が取り除かれた → 新は移行で記法を取り除く(決まったこと 4)
- 記法の壊れた説明文(migration-anomalies.md の 14 の A〜E): 旧は、崩れた文字(`p`・`@` など)が混じったまま表示していた → 新は、移行で正しい記法に直して表示する(決まったこと 9。#393)
- 消えたカクテルを指す `@c<ID>@`(14 の F): 旧は、無いカクテルを指したまま残っていた → 新は、移行で記法を取り除く(決まったこと 9。#393)
- 記法の外の `@`・`＠`(A〜F 以外。ID の無い `@p@`・メールアドレスなど): 旧は `@` を含めたまま持っていた → 新は、移行で `@`・`＠` を取り除いて文字だけを残す(決まったこと 6・9。#393 のオーナーのコメントで決めた)
