# 条件検索の並べ替えとページング

#167 で決めたこと。条件検索の API(`POST /api/cocktails/search`)は、旧と違って結果をページに切って返す(`docs/decisions/search-screen.md` の決まったこと 5)。そのため、旧が画面(旧 `Results/Tables/Cocktails.vue`)で行っていた並べ替えを、サーバーで行う。`docs/search.md` の「新しい条件との対応」で #167 に預けていた、`sort` の値の名前・カタカナとひらがなの寄せ方・値の無いものの位置を、ここで決める。

## 決まったこと

1. **`sort` の値は、旧の画面の並べ替えの鍵の名前**(応答の項目の名前とも同じ): `method`(製法)・`name`(名前)・`name_eng`(英名)・`base`(ベース)・`recipe_count`(必須)・`sweet_degree`(甘さ)・`rate`(評価)・`strength`(度数)・`youtube`(動画)。既定の並び(ID の順)を URL に残せるよう、`id` も受ける。省くと `id`
2. **`order` は `asc` / `desc`**。省くと、旧の画面で見出しを最初に押したときの向き(`sweet_degree`・`rate`・`strength`・`youtube` は降順、ほかは昇順)
3. **比べ方は旧の画面と同じ**
   - 製法は技法の ID、必須・甘さ・評価・度数は数として比べる
   - 名前・ベース(ベースのノードの名前)は、カタカナをひらがなに、全角の英数字を半角にそろえて比べる(旧の `Helper.katakanaToHiragana`。管理画面の一覧の `AdminListName::fold` と同じ)。大文字・小文字はそろえない
   - 英名は小文字にそろえて比べる
   - 文字列は、JS の文字列の比較と同じく UTF-16 の符号の単位の順で比べる(照合順序は使わない)
   - 動画は、動画のあるものどうしをカクテルの更新日時で比べる
4. **値の無いものは、向きによらずいつも最後**: 甘さ・評価・英名が null のもの、動画が無いもの
5. **同じ値のものは、どちらの向きでも ID の昇順**(#167 の本文)
6. **ページングは `page`(1 から)・`per_page`(1〜50。省くと 50)**。応答は `data` に 1 ページ分、`meta` に件数(`current_page`・`per_page`・`total`・`last_page` など)と、`links` を返す(Laravel のページ付きのリソースの形。管理画面の一覧 #289 と同じ)。最後のページより後は、空の `data` と件数を返す。このエンドポイントは POST で条件が本文にあり、`links` は `path?page=N` だけの GET の URL になる(`sort` などが入らない)ので、FE は `links` をたどらず、`meta` の `current_page`・`last_page` から `page` を組み立てて、同じ条件で POST し直す
7. `sort`・`order`・`page`・`per_page` が決まった値でなければ 422(`category_ids` と同じく、真偽値・小数は整数として受けない)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/search-sort.md)` としてここを指す。

- 英名の無いカクテルを英名で並べたとき: 旧は null と文字列の比較が定まらず(どちらの順でも「小さい」になる)、並びがブラウザの並べ替えの作りしだいだった → 新は向きによらず最後(決まったこと 4)
- 動画のあるカクテルどうしで、更新日時が同じとき: 旧は日時を `Date` のオブジェクトのまま `===` で比べるので同じにならず、並びが定まらなかった → 新は ID の昇順(決まったこと 5)
- 並べ替える範囲: 旧は条件に合う全件を画面で並べ替えた → 新はサーバーで全件を並べ替えてから、1 ページ分を返す(並びは旧で全件を並べた順を、ページに切ったものになる。ページングそのものは `docs/decisions/search-screen.md` の決まったこと 5)

`sort=id`・`sort` を省いて `order=desc`・値の検証(422)は、旧に無い(旧の API には並べ替えとページの条件が無かった)。

## 理由

- **比べ方を旧の画面に合わせる**: 旧の利用者が見ていた並びを変えないため。SQL の照合順序(`utf8mb4_unicode_ci`)では、カタカナとひらがなの寄せ方・濁点の扱いが旧の JS と合わないので、管理画面の一覧(#289)と同じく、当たったカクテルの並べ替えに使う列だけを読んで PHP で並べる。当たる件数は多くても旧のカクテル全体(約 5,700 件)
- **値の無いものを最後にする**: 旧で決まっていた甘さ・評価・動画に合わせ、旧で定まっていなかった英名も同じにする
- **`sort` の名前を旧の鍵と応答の項目に合わせる**: 画面が、表の列と並べ替えの値を 1 つの名前で扱えるため

## 旧ソースで確かめた事実

画面の Vue のソース(`laravel6/resources/js/components/Results/Tables/Cocktails.vue`)を読んだ。

| どこ | 何をしているか |
|---|---|
| `sortedList` | API が返した順(ID の昇順)の配列を `Array.prototype.sort` で並べる。比べた結果に、昇順なら 1、降順なら -1 を掛ける |
| `method` | `method.method_id` で比べる |
| `sweet_degree`・`rate` | どちらかが null なら、向きによらず null を後ろにする |
| `base`・`name` | `Helper.katakanaToHiragana` でそろえて比べる(`base` はベースの名前) |
| `youtube` | どちらかの `youtube` が null なら、向きによらず null を後ろにする。両方あれば `new Date(updated_at.date)` で比べる |
| それ以外(`name_eng`) | 値があれば `toLowerCase` して比べる。null はそのまま比べる |
| `sortBy` | 同じ列を押すと向きが入れ替わる。最初に押したとき、`strength`・`sweet_degree`・`youtube`・`rate` は降順、ほかは昇順 |

旧の画面を動かしての確かめ(実測)はしていない(#167 はクラウドで実装し、旧を動かせなかった)。
