# 度数の計算と、有名な銘柄を持たないノードの扱い

#158 で決めたこと。カクテルの度数(`cocktails.volume`)は、保存のときに材料から計算して持つ(計算は `StrengthCalculator`。#160)。材料に銘柄が無いときは、材料のノードの「有名な銘柄」(`categories.famous_brand_id`)の度数を使う。旧の計算は固定の 2 段(カテゴリ・ミドル)を前提にしていたので、任意の深さの木で、有名な銘柄を持たないノードをどう扱うかを決めた。

## 決まったこと

オーナーが案 X を選んだ(#158 のコメント)。

1. **有名な銘柄は、保存のときの検証で必須にする**(旧と同じ)。対象は、根の役割(#153)が null の部分木(洋酒など)のノード。既存の銘柄を選ぶか、ノードの編集画面のその場で銘柄を作る。DB の列は null 可のまま
2. **度数の計算は、材料のノードに有名な銘柄が無ければ 0%**(旧と同じ)。祖先のノードの有名な銘柄は使わない。材料が銘柄を持つときは、その銘柄の度数を使う(旧と同じ)
3. **有名な銘柄は、そのノードの部分木にぶら下がる銘柄から選ぶ**。別の系統の銘柄は選べない
4. **移行した度数は、旧の値をそのまま移す**(計算し直さない。#31)。有名な銘柄を持たないノードは `data:verify`(#157)で一覧に出し、埋める
5. 採らない案: 有名な銘柄が無ければいちばん近い祖先の有名な銘柄を使う案(Y)と、移行したノードだけ祖先の銘柄を使う案(X + Y)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/strength.md)` としてここを指す。

- ミドルの有名な銘柄に選べる銘柄: 旧はミドルのノードの銘柄に加えて、親のカテゴリの直下の銘柄(どのミドルにも属さないもの)も選べた → 新はそのノードの部分木にぶら下がる銘柄だけ(決まったこと 3)
- 有名な銘柄がそのノードの部分木の銘柄かどうか: 旧はサーバーでは確かめず、画面の候補の絞り込みだけだった → 新は保存のときの検証で確かめる(決まったこと 3)
- 3 段目以降のノードで有名な銘柄が無いとき: 旧はカテゴリ・ミドルの固定 2 段だけで、3 段目以降のノードが無かった → 新は祖先の銘柄を使わず 0% とする(決まったこと 2)

度数の計算(決まったこと 2。旧にもある 2 段のノードについて)と、有名な銘柄を必須にする範囲(決まったこと 1)は旧と変えない。

## 理由

- **DB の必須(NOT NULL)にしない**: ソフトドリンク・その他の部分木には銘柄という考えが無い。また銘柄はノードにぶら下がるので、ノードを作る瞬間には、その下に銘柄がまだ無い(ノード → 銘柄の順でしか作れない)。旧は、ノードの保存と同じリクエストで銘柄も作って、これを避けていた
- **保存のときの検証で必須にする(案 X)**: 旧の運用と同じで、計算の規則が 1 つで済む。祖先の銘柄を使う案(Y)は、どの銘柄の度数で計算したかが画面から見えにくく、祖先の銘柄を変えると、配下のカクテルの正しい度数が変わる(保存し直すまで反映されない)
- **部分木の銘柄から選ぶ**: 有名な銘柄はそのノードの代表なので、別の系統の銘柄を選べると、計算した度数が材料と関係の無い銘柄の値になる

## 旧ソースで確かめた事実

本番の BE(`laravel13/`)と画面(`laravel6/resources/js/`)を読んだ。

| どこ | 何をしているか |
|---|---|
| 度数の計算: `laravel13/app/Classes/Factory/RecipeCalc.php` の `calcStrength`(`FactoryHelper` のカクテルの保存から呼ぶ) | 材料が銘柄を持てば、その銘柄の度数。持たなければ、材料のミドル(ミドルが無ければカテゴリ)の `famous_brand_id` の銘柄の度数。`famous_brand_id` が null か 0 なら 0%。**ミドルに有名な銘柄が無いとき、親のカテゴリの有名な銘柄は見ない** |
| ノードの編集の検証: `laravel13/app/Http/Requests/Detail/Edit/EditCategoryValidate.php`・`EditMiddleValidate.php` | 種別 1〜3 では、`brand_id`(既存の銘柄)が無ければ、その場で作る銘柄の名前・英名・度数(数)・説明・メジャー・お気に入りが必須(`required_without:brand_id`)。種別 4・5(`KindFactory::is_kind5_fromKindId`)では、名前・英名・度数・説明のどれかが入っているときだけ必須 |
| その場で作る銘柄: `laravel13/app/Http/Controllers/Auth/DetailEditController.php` の `insertFamousBrand` | `brand_id` が無く銘柄の名前があれば、銘柄を作ってそのノードの有名な銘柄にする |
| 有名な銘柄の候補: `laravel6/resources/js/Admin/Super/Detail/component/FamousBrandSelect.vue` の `select_brand` | カテゴリの編集では、そのカテゴリの銘柄(ミドルに属するものも含む)。ミドルの編集では、同じカテゴリの銘柄のうち、そのミドルに属するものと、**どのミドルにも属さないもの**。サーバー側には候補の検証が無い |
| 有名な銘柄の所属の変更: `laravel13/app/Classes/Factory/FactoryHelper.php` の `generateFromRequest` | 有名な銘柄になっている銘柄のカテゴリ・ミドルを変えようとすると拒む。ミドルを別のカテゴリへ移すとき、元のカテゴリの有名な銘柄がそのミドルの銘柄なら拒む |

- 計算は「材料のノード自身の有名な銘柄」しか見ないので、祖先の銘柄を使わない決まったこと 2 は旧と同じ
- 旧の種別(`m_category_kinds`)には `famous_brand_id` の列が無い

## 旧 DB で確かめた事実

手元に復元した本番の旧 DB のダンプ(カクテル 5,707 件)で数えた。

| 数えたもの | 件数 |
|---|---|
| 種別 1〜3 のカテゴリで、有名な銘柄が無い(null か 0) | 0(136 件中) |
| 種別 1〜3 のミドルで、有名な銘柄が無い | 0(142 件中) |
| 種別 4・5 のカテゴリで、有名な銘柄が無い | 139(145 件中。ある 6 件は種別 4 で、どれも度数 0) |
| 種別 4・5 のミドルで、有名な銘柄が無い | 137(139 件中。null が 18、0 が 119) |
| ― そのうち、親のカテゴリには有名な銘柄がある | 3(どれも種別 4) |
| ミドルの有名な銘柄が、そのミドルの銘柄でない | 1(ミドル 58) |
| カテゴリの有名な銘柄が、そのカテゴリの部分木の銘柄でない | 1(カテゴリ 197。下のとおり、移行すると部分木に入る) |

- **#158 の本文の「旧データには、有名な銘柄が無いノードが残っている可能性がある」は、種別 1〜3 では 0 件だった**。有名な銘柄が無いのは、ソフトドリンク・その他(必須でない部分木)のノードだけ
- ミドル 58(親はカテゴリ 94)の有名な銘柄は銘柄 138 で、銘柄 138 はカテゴリ 94 の直下(どのミドルにも属さない)。旧の画面の候補(上の `select_brand`)で選べたもの。新しい木ではミドル 58 の部分木の外になり、決まったこと 3 に反する(下の「決まったことに書かれていないこと」)。ミドル 58 を使い銘柄を持たない材料は 2 行(2 カクテル)で、度数 14% の銘柄 138 で計算されている
- カテゴリ 197 の有名な銘柄(銘柄 251)は、カテゴリの列が 2 だが、ミドル 126(親はカテゴリ 197)に属する。`docs/migration-anomalies.md` の 4 で、ミドルの親(カテゴリ 197)に合わせて移すと決めているので、移行するとカテゴリ 197 の部分木に入る。数えなくてよい
- 種別 4 の 3 件のミドルは、親のカテゴリに有名な銘柄があっても旧の計算では 0%(親の銘柄を見ないため)。親の銘柄もどれも度数 0 なので、どちらでも結果は変わらない

数えた SQL:

```sql
-- 種別ごとの、有名な銘柄が無いノード
SELECT kind, COUNT(*), SUM(famous_brand_id IS NULL OR famous_brand_id = 0) FROM m_category GROUP BY kind;
SELECT c.kind, COUNT(*), SUM(mi.famous_brand_id IS NULL OR mi.famous_brand_id = 0),
       SUM(mi.famous_brand_id IS NULL), SUM(mi.famous_brand_id = 0)
FROM m_middle mi JOIN m_category c ON mi.parent = c.id GROUP BY c.kind;
-- 有名な銘柄が無く、親のカテゴリにはあるミドル: 3 件
SELECT COUNT(*) FROM m_middle mi JOIN m_category c ON c.id = mi.parent
WHERE (mi.famous_brand_id IS NULL OR mi.famous_brand_id = 0) AND c.famous_brand_id > 0;
-- ミドルの有名な銘柄が、そのミドルの銘柄でない: ミドル 58
SELECT mi.id, b.id, b.category, b.middle_category FROM m_middle mi JOIN m_brand b ON b.id = mi.famous_brand_id
WHERE NOT (b.middle_category <=> mi.id);
-- カテゴリの有名な銘柄が、そのカテゴリとそのミドルの銘柄でない: カテゴリ 197
SELECT c.id, b.id, b.category, b.middle_category FROM m_category c JOIN m_brand b ON b.id = c.famous_brand_id
LEFT JOIN m_middle m ON m.id = b.middle_category
WHERE NOT (b.category <=> c.id) OR (b.middle_category > 0 AND NOT (m.parent <=> c.id));
-- ミドル 58 を使い、銘柄を持たない材料: 2 行・2 カクテル
SELECT COUNT(*), COUNT(DISTINCT r.cocktail_id) FROM t_recipies r JOIN t_cocktails t ON t.id = r.cocktail_id
WHERE r.middle_category = 58 AND (r.brand IS NULL OR r.brand = 0);
```

## 決まったことに書かれていないこと

- **ミドル 58 の扱い**: 移行したデータでは、有名な銘柄(銘柄 138)がノードの部分木の外にある。`data:verify`(#157)の追記は、これを警告ではなく失敗にしている。移行で銘柄 138 をミドル 58 の下へ移すか、有名な銘柄を外すか(外すと 2 カクテルの材料が 0% の計算になる)、`data:verify` で警告にとどめるかは決まっていない
- **根のノード**: 根の役割が null の根(洋酒など)は、有名な銘柄を持たない(旧の種別に列が無い)。根は材料に使えない(`docs/decisions/category-root-role.md` の決まったこと 4)ので度数の計算には出てこない。そのため、決まったこと 1 の必須と 4 の一覧からは根を除く、と読んでいる(決まったことには書かれていない)
- **有名な銘柄になっている銘柄の所属の変更**: 旧は少しでも変えると拒んでいた。部分木の中での移動を許すか(#314 の 4)は、#158 では決めていない。#314 で、決まったこと 3 に合わせて、有名な銘柄にしているノードの部分木の中への移動は許し、外へ移すときは 422 で理由を返すことにした(`AdminBrandWriter`)
