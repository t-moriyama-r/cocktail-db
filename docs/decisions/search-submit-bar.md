# 条件検索のモーダルで、「材料は必須です。」を検索ボタンと一緒に下端に貼り付ける

#576 で決めたこと。ヘッダーのモーダルで条件検索のフォーム(#307)を開いた直後に、下端に貼り付けた「検索」ボタンが、すぐ上の「材料は必須です。」の枠にかぶって、押せない理由が読めない幅があった。

## 決まったこと

1. モーダルの中では、「材料は必須です。」を検索ボタンと同じ帯に入れ、ボタンの上に置いたまま、一緒にモーダルの下端に貼り付ける。開いた直後(材料 0 個)でも、スクロールの途中でも、文言とボタンが重ならずに見える
2. 貼り付けているあいだは、後ろの材料の欄が透けないよう、文言の枠の地を塗る(`--color-surface`)。帯の文言とボタンの無いところは、今までどおり透かし、押すと後ろの材料の欄に届く
3. トップのページ内(モーダルでないところ)は、帯に入れても見え方を変えない(材料の欄の下に文言、その下に検索ボタン。間の空きも同じ)

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/search-submit-bar.md)` としてここを指す。

- モーダルの中の「材料は必須です。」(旧は「カテゴリは必須です。」)の位置: 旧は検索ボタンだけを画面の左下に固定し、文言は材料の欄の下に置いたまま固定しなかった(旧ソースから。旧を動かしての見え方は確かめていない) → 新は文言も検索ボタンの上に付けて一緒に下端に貼り付け、ボタンに隠れない

## 理由

- 押せない理由(材料が 0 個)を読めないと、押せないボタンだけが見えて、何をすればよいか分からない。文言とボタンを離すと、どの位置で開いても「ボタンの真後ろに来る行」ができ、そこに文言が来る幅が残る。同じ帯に入れれば、幅・高さ・スクロールの位置によらず重ならない
- 文言は検索ボタンの `aria-describedby` で読み上げにも結び付けていて、見た目でもボタンの近くに置くほうが対応が分かりやすい

## 旧ソースで確かめた事実

画面(`laravel6/resources/js/components/Forms/Search/Cocktail/form.vue`)を読んだ。旧システムを動かしての確認はしていない。
