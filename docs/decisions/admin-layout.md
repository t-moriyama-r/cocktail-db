# 管理画面の枠とメニュー

#119 で決めたこと。決めたのは #119 の本文の「追記: 旧の画面で確かめた仕様」(オーナーが書いた)で、ここはそれを、テストの表から指せる「旧との差分」の節にまとめたもの。ログインの後の行き先は #284 で決めた(`docs/decisions/admin-screens.md` の 7)。

## 決まったこと

1. 管理画面(`/admin` 以下。ログインの画面を除く)は、どの画面にも、上に管理画面の題(メニューへのリンク)とメニューを出す
2. メニューの並びは、カテゴリ木 / 銘柄 / カクテル / 用語辞典 / 言い換え・スキップ語 / 設定 / パスキー / ログアウト。まだ画面の無い項目は出さず、その画面の issue で足す(並べる項目は `frontend/src/components/AdminLayout/adminMenuItems.ts`)
3. 旧のメニューの項目は、次のように扱う

   | 旧の項目 | 新 |
   |---|---|
   | カテゴリ新規・編集 / ミドルカテゴリ新規・編集 | 「カテゴリ木」1 つ(#123) |
   | 銘柄新規・編集 | 引き継ぐ(#64) |
   | ドラフト編集 / カクテル新規・編集 | 「カクテル」(公開済み・下書き・新規。#126) |
   | オートインプット実行・該当ページを開く・カウント+1 | 引き継がない(#68) |
   | 用語集・パラフレーズ(旧はコメントアウト) | 新しく作る(#66・#67) |

4. メニューの最後にログアウトを出す。ログアウトしたらログインの画面(`/admin/login`)へ移り、その後は `/admin` 以下を開くとログインの画面へ移る
5. 未ログインで `/admin` 以下を開くと、開こうとしていた URL(パス・クエリ・ハッシュ)を `?redirect=` に持たせてログインの画面へ移す。ログインの後はその URL へ戻す(`docs/decisions/admin-screens.md` の 7)。戻すのはこのサイトの `/admin` 以下だけで、ほかのサイト・公開ページ・ログインの画面そのものを指していれば、メニュー(`/admin`)へ移す

## 旧との差分

テストの表では `差分あり(意図: docs/decisions/admin-layout.md)` としてここを指す。

- 管理画面の枠: 旧は管理画面にヘッダーもメニューの枠も無く、`/admin` がリンクを縦に並べたメニューのページで、各画面からメニューへ戻るリンクも無かった → 新はどの管理画面にも、上に題(メニューへのリンク)とメニューを出す
- オートインプット: 旧のメニューには「オートインプット実行」「該当ページを開く」「カウント+1」があった → 新はメニューに出さない(#68 で引き継がない)
- ログアウト: 旧のメニューにはログアウトが無かった → 新はメニューの最後に出す

ログインの後の行き先(旧は必ず `/admin`)の差分は、`docs/decisions/admin-screens.md` の「旧との差分」にある。
